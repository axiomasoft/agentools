# Current context and disclosure boundaries (platform/v1 additive)

BoundaryGuard uses the trusted ExecutionContext factory, current HostAuthorization,
exact snapshot revision/hash, emergency state, current source access and current
tool definition/schema tuples. Unknown is denied explicitly. It checks every
boundary again; a snapshot, classifier result, cached skill or checked payload is
never a capability. All text/raw/build/stream/voice/background/scheduled entries
use the same checks. Security retains its Common-only module boundary.

Context GuardSnapshot adapts the existing compiler/trust model. It verifies the
compiled hash/scope and selected block manifests against the exact plan, rejects
missing mandatory blocks, and supplies current owner probes with derived refs,
source message IDs, bundle/skill/material/cache dependencies and capability pins.
Every source policy call receives the exact SnapshotEvidence, so deployment/skill
qualification requires no mutable per-request singleton state.
Host BoundaryPolicy must resolve exact immutable versions and current rights,
including Profiles assertPin/use, Composer.prepare at the execution boundary,
skill qualification tuple/revoke, summary/candidate dependency validity and source
consent/expiry. Unknown source freshness must return unknown, never a cached allow.
These required ports have no permissive production implementation.

Runtime GuardedTransport wraps the existing one-exchange ModelTransport per
invocation. RequestRenderer must serialize exactly the same concrete API form and
version as the compiler Renderer, including policy, tools, model parameters,
cache/continuation intent and provider layout overhead. The wrapper checks both
rendered bytes/hash and exact projected schema tuples, and pins the host-selected
opaque credential ref. The actual credential owner still authorizes resolution;
model/source text cannot choose arbitrary credential refs. It repeats current guards,
serialization binding and capability/deadline/cancellation checks immediately
before provider IO. Host composition must install this wrapper at the actual
transport boundary; the original Runtime/SDK API and existing guards remain.
The scripted adapter demonstrates the contract, not live tokenizer/provider support.

DisclosureStream is per response/version/invocation. Buffered mode retains bytes
transiently and checks the whole response before producing any releasable payload.
Sensitive snapshot/output policy requires buffered mode. Checked segments release
only closed, fully checked segments. Live mode requires a separate explicit risk
approval and labels payloads prechecked=false; it promises no token pre-review.
Policy changes require a new finalization/disclosure session rather than silently
weakening the selected mode. Stream size/sequence bounds refuse; they never truncate.

Generated bytes, pending checked payloads, delivery and hearing are separate facts.
Every delivery rechecks current permissions/revision/source rights. Payload identity
is tenant/response ref/version/ordinal scoped and survives policy/snapshot refresh;
changed bytes under the same identity require an owner hash conflict, never a new
idempotency key. Response refs must identify the host run/response; the delivery
owner separately scopes destination delivery identity. The final
DisclosureDelivery owner must reauthorize at actual IO and persist same-key
receipts/outbox. Completed generation is not delivery acknowledgement. Generic
owner IO exceptions become a local unknown observation, never zero/success or an
automatic resend; the host reconciles durable delivery status. Typed mandatory
permission refusals propagate. Interruption records actual delivered/heard counts,
stops remaining content and preserves receipts. Provider/response IDs are fixed;
a second provider response cannot be stitched after partial disclosure.

There is no distributed lock across external owners. Hosts must durably deliver
revocation/consent events and enforce current rights again at their own writes and
disclosure. These checks do not replace Actions confirmation/authorization or
accounting/admission. No parallel effect-capable loop or second conversation owner
is introduced.

WorkerScope constructs context per job, resets every tenant/actor/credentials/
policy/profile/retrieval/payload resource before and in finally after the job,
attempts all reset owners and quarantines the worker on reset failure. Health is
the only mutable state it retains; hosts own actual connection/resource reset.
LogProjection accepts typed technical links/codes and drops all untrusted nested
fields plus exception messages/stacks/previous chains. It does not change mandatory
authorization/accounting failures. Hosts choose optional observability failure
policy and must use this closed projection at their logger boundary. Full prompts
are absent from default logs; separately authorized encrypted Diagnostics with
TTL/access/audit remains the P7.4 port. Diagnostic refs alone confer no access.

Generate JSON examples with `php packages/agentools-core/tests/Security/generate.php`.
Evidence is contract-scripted. P7.6 Grok aggregate review and V1/V2 are conductor
owned. The review pack indexes actual P7.1-P7.5 source hashes, receipts, deviations
and owner obligations without claiming a review was dispatched or completed.
Historical P6.5/P4.4/P5.2/ManualClock/P3.5 risks and D8 remain unchanged.
