### P9.4 — Сгенерировать и проверить SPDX SBOM, SLSA provenance и conditional GitHub attestation

**Intent:** Связать каждый exact P9.3 subject с валидным SPDX 2.3 SBOM и SLSA v1.2 provenance, а GitHub attestation выпускать только при доказанной hosted capability.
**Why:** Lockfile inventory, archive contents, provenance statement и signed platform attestation отвечают на разные вопросы; смешивание их даёт ложную supply-chain гарантию. `RAG:✅` в `research/P9-design-rag.md`.
**Scope Included:** Normative SPDX 2.3 JSON per subject; separate source/lock and extracted-artifact catalogs; pinned Syft generation plus independent schema/tool validation; exact subject/package/checksum reconciliation; optional CycloneDX derivative only при named consumer; SLSA v1.2 provenance predicate with build definition/run materials; offline verification; conditional full-SHA-pinned `actions/attest` path and explicit capability status.
**Scope Excluded:** Vulnerability-free claim from SBOM; runtime correctness; keyless attestation outside trusted hosted identity; pretending an unsigned local statement is a GitHub attestation; mandatory CycloneDX duplication; public transparency/publication; long-lived signing keys.
**Inputs:** P9.3 exact subjects/content manifests/checksums · `.ci/supply-chain-lock.json` · package lockfiles · source/tree identity · P9.1 capability inventory · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/root/contracts/release-candidate-v1.md`.
**Files:** `tools/sbom_gate.py` · `tests/tools/test_sbom_gate.py` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P9-supply-chain-evidence.json` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/P9-supply-chain-evidence.md`.
**Required Reads:** 1) P9.1 and P9.3 contracts/receipts 2) exact package manifests/locks and extracted subject content manifests 3) SPDX 2.3 conformance/tools, Syft catalogers, SLSA provenance v1.2 and GitHub artifact-attestation primary sources cited in `research/P9-design-rag.md` 4) `decisions/D14-ci-private-rc-evidence.md` 5) D4 release gate and D12 MCP companion blocker.
**Implementation Rules:** SPDX 2.3 JSON is the sole normative SBOM format for P9; CycloneDX is emitted only as a declared non-normative derivative when a concrete consumer is recorded. Scan lock/source inputs and extracted exact subjects separately and retain both results. Every release subject has a unique SBOM namespace, SHA-256 subject binding and validated package/file relationships; tool output alone is insufficient without schema and reconciliation checks. Provenance subject digest equals the P9.3 archive digest and materials include source/tree, contract, content-manifest and tool-lock digests. Use the current unified `actions/attest` action at a reviewed full commit SHA, with `id-token: write`/`attestations: write` only in the attestation job. Private/internal GitHub attestation is `unavailable-plan` unless Enterprise Cloud capability is positively proved; local provenance remains `statement-verified`, never `attested`.
**Code Guidance:** Make generation and verification separate commands and corrupt each relationship in tests. Preserve raw Syft/SPDX validator versions and outputs by digest. Do not scan the enclosing workflow artifact and call that the package SBOM. Keep platform bundle/download identifiers separate from release-file digests. Design the evidence receipt so `verified`, `unavailable-plan`, `available-disabled` and `not-executed` cannot collapse into pass.
**Validation:** Official SPDX validation and independent relationship/checksum checks pass for every exact subject; fixtures with stale lock, omitted archive file, wrong namespace, wrong subject digest or malformed relation turn red; provenance validates against SLSA v1.2 shape and exact materials/subject digest; offline verifier catches any mutation; attestation path has full-SHA action pin and minimum job permissions; unavailable/not-executed hosted capability remains explicit and cannot emit `attested=true`; no public release or signing secret is created.
**Deliverables:** Validated normative SPDX SBOMs, exact SLSA provenance statements, conditional GitHub attestation contract/path and supply-chain evidence receipt for P9.5/P10.
