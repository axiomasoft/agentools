### P9.3 — Собрать канонические воспроизводимые private RC subjects и receipt schema

**Intent:** Построить три repository-owned normalized package subjects и доказать byte-for-byte воспроизводимость в независимых clean directories.
**Why:** Native package preview/archive commands помогают проверить contents, но не обещают одинаковые archive bytes; provenance обязана ссылаться на заранее определённый exact subject. `RAG:✅` reproducible-build and packaging evidence в `research/P9-design-rag.md`.
**Scope Included:** Canonical private RC identity; PHP, Dart core и Dart MCP companion subjects; P7 allowlist/content-manifest consumption; normalized path order, metadata, modes, ownership, timestamps and gzip header; `SOURCE_DATE_EPOCH` from source commit; canonical content manifest; SHA-256 checksum set; two independent clean builds; schema-versioned per-subject and aggregate receipt contract; explicit private paired-artifact status for MCP path dependency.
**Scope Excluded:** Composer/pub registry-compatible byte identity claim; public version/tag; registry upload; SBOM/provenance generation; GitHub workflow transport; changing package contents or dependencies; treating a source checkout tarball as the package.
**Inputs:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P7-package-gate.json` · `findings/P7-package-gate.md` · package manifests/locks · source commit/tree identity · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/decisions/D12-intentional-package-surfaces.md` · `D14-ci-private-rc-evidence.md`.
**Files:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/root/contracts/release-candidate-v1.md` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/root/contracts/release-candidate-v1.schema.json` · `tools/release_candidate.py` · `tests/tools/test_release_candidate.py` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P9-reproducibility.json` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/P9-reproducibility.md`.
**Required Reads:** 1) `phases/P7/P7.closed.md` and executed P7 manifests/receipts 2) package manifests, locks, ignore/export rules and generated-file ownership 3) `research/P9-design.md` and reproducible archive/Composer/Dart sources in `research/P9-design-rag.md` 4) `decisions/D12-intentional-package-surfaces.md` and `D14-ci-private-rc-evidence.md` 5) `plans/AGENTOOLS/root/contracts/package-quality-baseline.md` 6) P9.1 tool lock.
**Implementation Rules:** The canonical subject format is repository-owned POSIX tar plus deterministic gzip: bytewise sorted normalized relative paths, rejected traversal/symlink escape/special files, fixed owner/group IDs and names, fixed modes by declared executable policy, fixed mtime from source commit, deleted variable PAX atime/ctime headers and gzip name/time suppression. Build roots and output paths never enter contents. Two builders use separate clean copies and no shared package cache for assembly. Native Composer/Dart previews and P7 manifests are independent content oracles, not canonical byte producers. RC identity is source/contract based and cannot imply a public semver/tag. MCP companion stays `private-paired`/`public-release-blocked` while it has a path dependency.
**Code Guidance:** Separate content selection from archive serialization and checksum receipt writing. Refuse dirty/untracked product inputs unless explicitly represented in a test fixture. Stream hashes and archive entries; record source/tree/manifest/tool-lock/algorithm digests. Compare content manifests before archive digests so a mismatch is diagnosable. Keep SBOM/provenance outside subject bytes to avoid self-reference.
**Validation:** Golden fixtures cover path ordering, Unicode names, executable modes, symlinks, traversal, variable umask/timezone/locale and PAX/gzip metadata; two clean builds under varied temp roots/umasks/locales produce identical content-manifest and archive SHA-256 for all three subjects; one byte/mode/path/metadata mutation turns red; exact P7 allowlists match with no missing/extra files; schema rejects unknown algorithms/digests/statuses; MCP public-release blocker is preserved; no tag/upload/registry credential is used.
**Deliverables:** Normative private-RC contract/schema, deterministic builder, three exact candidate subjects with SHA-256/content manifests and independent reproducibility receipt.
