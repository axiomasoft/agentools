# P9 — CI, supply chain и reproducible release artifacts

## Phase Context

P9 переводит доказательства P1–P8 в две явно разделённые плоскости: untrusted CI для
изменений и trusted private release-candidate assembly. Фаза создаёт least-privilege,
full-SHA-pinned workflows, dependency matrices, воспроизводимые package subjects,
checksums, SPDX SBOM, SLSA provenance и честные capability-qualified receipts. Она не
публикует package, tag или release и не меняет настройки GitHub.

> **Контракт фазы (contract-first).** Потребляет: P1 support/resource contracts, P7
> package manifests и clean-consumer evidence, P8 tiered commands/receipts. Производит:
> `ci-supply-chain-v1`, `release-candidate-v1`, hardened workflows и private RC evidence
> для P10. Граница: public publication остаётся за G-RELEASE.

> **Phase Assurance | v1.**
> Impact: security-external
> Integration Seams: github-actions · dependency-matrices · package-archives · sbom · provenance-attestation
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: SHA-pinned least-privilege workflows, exact artifact subjects и independent clean rebuild защищают supply chain; Review=full.

## DoR (Definition of Ready)

- [ ] P1 compatibility/resource contracts, P7 package gate и P8 aggregate receipt terminal и digest-verifiable.
- [ ] GitHub Actions/repository capabilities инвентаризированы read-only; недоступная licensed capability не выдаётся за GREEN.
- [ ] Canonical archive algorithm, allowed nondeterminism и subject identity заданы до сборки.
- [ ] Каждый внешний action/tool имеет reviewed version, immutable pin/digest и provenance source.
- [ ] G-RELEASE не требуется: workflow, local/private artifacts и dry-run не создают public tag/upload.

## Dependencies

`P1–P8 -> P9.1 -> P9.2`; `P7.4 + P9.1 -> P9.3 -> P9.4 -> P9.5`;
`P8.5 + P9.2 -> P9.5`. P10 принимает exact subjects и receipts, но не переопределяет
их digest или provenance.

## Execution Contours

- `ci-hardening`: P9.1–P9.2 разделяют contract/tool lock и workflow integration.
- `rc-evidence`: P9.3–P9.4 разделяют deterministic bytes и metadata/attestation.
- `solo`: P9.5 ждёт immutable child evidence и независимо проверяет aggregate candidate.

## Scope Excluded

Public registry upload, Git tag/release, publication credentials, GitHub settings/branch-protection
mutation, legal/license identity, mandatory paid GitHub capabilities, runtime-correctness claims
из подписи, и использование workflow artifact digest как release-file digest.

## Validation

Policy checker отклоняет mutable action refs, excessive permissions, unbounded jobs и unsafe
untrusted-code transitions. Supported/lowest/latest matrices используют свежие dependency
resolutions и не питают RC. Две чистые сборки дают идентичные normalized archives/content
manifests/SHA-256. SPDX и SLSA statements ссылаются на exact subject digests. Aggregate receipt
сохраняет отдельные capability states и не называет локальную provenance statement GitHub
attestation, когда hosted capability недоступна или не запускалась.

## Phase Handoff

P10 получает три exact private RC subjects, checksums/content manifests, normative SPDX SBOMs,
SLSA provenance, hosted-attestation status, CI/P8 evidence map и aggregate receipt. Только P10/G-RELEASE
может принять public identity и разрешить registry/tag/release.
