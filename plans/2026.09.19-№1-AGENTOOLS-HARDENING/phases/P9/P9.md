# P9 — CI, supply chain и reproducible release artifacts

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается `design-phase: task:plan-design 2026.09.19-№1-AGENTOOLS-HARDENING P9`

P9 превращает проверки в least-privilege CI и собирает воспроизводимые PHP/Dart release-candidate
archives с checksums, SBOM и provenance. Workflow создаёт доказательства, но не публикует package,
tag или release без owner gate.

> **Контракт фазы (contract-first).** Потребляет: gates, manifests и bounded suites P1–P8.
> Производит: hardened workflows, dependency matrices, archives, SBOM/provenance/attestations и receipts.
> Границы: registry credentials и public release принадлежат G-RELEASE/P10.

> **Phase Assurance | v1.**
> Impact: security-external
> Integration Seams: github-actions · dependency-matrices · package-archives · sbom · provenance-attestation
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: SHA-pinned least-privilege workflows и independent archive verification защищают supply chain; Review=full.

## DoR (Definition of Ready)

- [ ] P7 package manifests и P8 bounded CI tiers готовы.
- [ ] Supported PHP/Dart/dependency matrix следует P1 compatibility contract.
- [ ] Все third-party actions имеют full-length immutable commit SHA и минимальные permissions.
- [ ] Reproducibility definition и allowed nondeterminism заданы до сборки.

## Scope Included

Least-privilege permissions; action SHA pinning; timeouts/concurrency/cancellation; PHP supported and
lowest/latest dependency jobs; Dart supported/latest and `pub downgrade`; generated-drift, security,
consumer and archive gates; secret/dependency scanning where available; deterministic package archives;
checksums, SPDX/CycloneDX-compatible SBOM decision, SLSA-aligned provenance and GitHub attestations.

## Scope Excluded

Public registry upload/tag/release; long-lived publishing secrets; unsupported runtime promises;
mandatory cloud KMS; pretending attestations prove runtime correctness.

## Dependencies

P7 и P8, плюс P1 support matrix. P10 принимает созданный release candidate.

## Планируемый состав (черновик для детализации)

Workflow threat review; runtime/dependency matrices; gate integration; archive builders/inspectors;
SBOM/checksums/provenance/attestation; reproducibility verification и release-candidate bundle.

## Required Reads (порядок проектирования)

P1/P7/P8 deliverables; `.github/workflows/**`; package manifests/lockfiles; build scripts;
GitHub Actions security/attestation docs, SLSA provenance, Composer archive and Dart publishing docs.

## Files (ожидаемая область записи)

`research/P9-design.md`; `research/P9-design-rag.md`; workflows, build/verification scripts,
artifact manifests/reports и будущие item-спеки P9.

## Validation (ожидаемая форма)

Workflow permissions/pins проходят policy check; lowest/latest matrices зелёные; две clean builds
сравниваются по принятой reproducibility policy; archives имеют allowlisted contents, SBOM, checksum,
provenance и verification receipt без registry publication.
