### P9.5 — Собрать trusted private-RC workflow и aggregate verification receipt

**Intent:** Оркестрировать trusted private RC без public side effects и выпустить один digest-qualified receipt, который P10 может проверить независимо.
**Why:** Зелёные child jobs не доказывают, что один candidate собран из тех же inputs и subjects; hosted capability также нельзя подменять локальной симуляцией.
**Scope Included:** Trusted `private-rc` workflow; manual/protected-ref guards; isolated build, verify and optional attest jobs; minimum job permissions; exact P8 `release-candidate` tier; P9.2 CI map; P9.3 reproducibility; P9.4 SBOM/provenance/capability states; bounded artifact retention; independent download/re-hash verification; aggregate exact-set receipt and human finding.
**Scope Excluded:** Automatic push/dispatch from local execution; GitHub setting/secret/environment changes; tag/release/registry upload; public semver/license approval; accepting missing hosted evidence as present; rebuilding from lowest/latest matrix locks; changing child evidence.
**Inputs:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P8-adversarial-gate.json` · `artifacts/P9-ci-map.json` · `artifacts/P9-reproducibility.json` · `artifacts/P9-supply-chain-evidence.json` · `root/contracts/ci-supply-chain-v1.md` · `root/contracts/release-candidate-v1.md` · `.ci/supply-chain-lock.json`.
**Files:** `.github/workflows/private-rc.yml` · `tools/private_rc_gate.py` · `tests/tools/test_private_rc_gate.py` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P9-private-rc.json` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/P9-private-rc.md`.
**Required Reads:** 1) all P9.1–P9.4 contracts, locks, artifacts and findings 2) `phases/P8/P8.5.md` and executed aggregate P8 receipt 3) `plans/2026.09.19-№1-AGENTOOLS-HARDENING/decisions/D4-release-gate.md` and `D14-ci-private-rc-evidence.md` 4) GitHub secure-use/artifact/attestation primary sources in `research/P9-design-rag.md` 5) `phases/P10/P10.md` 6) all workflow/local-action dependencies.
**Implementation Rules:** Workflow starts at `permissions: {}`, runs only on explicit manual invocation and/or trusted protected refs defined by contract, and never executes fork/untrusted code or consumes untrusted caches/artifacts. Build/verify jobs receive `contents: read` only; only the conditional attest job receives `id-token: write` and `attestations: write`. Local execution always assembles and independently verifies subjects/SBOM/provenance/child receipts; it records hosted state as `not-executed` or capability-specific status. Platform artifact ID/digest proves transport, not release identity. Aggregate receipt enumerates exact child IDs/digests, subjects, checksums, matrices, P8 rows, tool lock, source/tree and capability states with no inferred pass.
**Code Guidance:** Verify after downloading into a fresh directory and before optional attestation. Use fail-closed exact-set joins and refuse stale source SHA, mixed run IDs, missing subjects or duplicate identities. Model `local_rc` and `hosted_attestation` as separate state machines. Static workflow tests must prove there is no tag/release/package-write path. Keep logs/artifact names free of secrets and set finite timeout/retention/concurrency.
**Validation:** Policy checker and malicious workflow fixtures prove least privilege, trusted trigger/ref, no untrusted transition and no public write scope; fresh local assembly plus independent verification produces exact aggregate with `missing=[]`, `extra=[]`, `stale=[]`; mutation of any child/subject/tool/source digest turns red; all applicable critical P8 RC rows are present; hosted status accurately distinguishes verified/unavailable/not-executed; when hosted attestation is available, downloaded bundle verifies against exact subject digests; workflow has no registry/tag/release command and requires no publication credentials; plan lint adds no ERROR.
**Deliverables:** Hardened private-RC workflow, independent verifier, exact aggregate P9 receipt and explicit hosted-capability finding ready for P10 acceptance.
