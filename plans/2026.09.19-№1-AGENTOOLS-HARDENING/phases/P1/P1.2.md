### P1.2 — Заморозить trust boundaries, data flows и threat/misuse model

**Intent:** Выпустить versioned threat contract, который явно разделяет trusted, partially trusted и untrusted inputs, показывает security/durability data flows и связывает misuse cases с owning phases P2–P10.
**Why:** Подтверждённые F01–F05 возникают на границах, где application caller сейчас поставляет security context, clock, authorizer, descriptor и process-local stores; без единой trust model каждая owning phase может локально «починить» неверную границу. `RAG:—` (`findings/audit-verdicts.md`, PHP/Dart ports and confirmation implementations).
**Scope Included:** Assets and security objectives; actors; trust zones; data-flow diagrams for descriptor/arguments/proposal/token/approval/commit, idempotency acquire/effect/complete and event append/load; attacker and accidental-integrator capabilities; abuse/misuse cases; tenant/cross-process/restart/replay/crash boundaries; mitigation owner and required negative evidence per threat; residual/out-of-scope risks.
**Scope Excluded:** Choosing exact P2 service API, P3 token format/crypto, P4 lease schema, P5 event DDL, release security policy or claiming a mitigation already exists.
**Inputs:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P1-baseline.json` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/P1-baseline.md` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/audit-verdicts.md` · `spec/revisions/2026-08/04_confirmation.md` · `spec/revisions/2026-08/09_idempotency-errors.md` · `spec/revisions/2026-08/10_security.md`
**Files:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/root/contracts/threat-model-v1.md`
**Required Reads:** 1) `plans/2026.09.19-№1-AGENTOOLS-HARDENING/artifacts/P1-baseline.json` 2) `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/audit-verdicts.md` 3) `spec/revisions/2026-08/04_confirmation.md` 4) `spec/revisions/2026-08/09_idempotency-errors.md` 5) `spec/revisions/2026-08/10_security.md` 6) `php/src/Confirmation/ConfirmationProtocol.php` 7) `dart/agentools/lib/src/confirmation/confirmation_protocol.dart` 8) `php/src/Contracts/IdempotencyStore.php` 9) `php/src/Contracts/EventLog.php`.
**Implementation Rules:** Each threat has stable `TM-###`, asset, entry point, prerequisite, impact, current disposition, owning PLAN1 phase/item class and proof type. `mitigated` is forbidden without current executable evidence; present gaps are `open`. Application integration code and tool/policy adapters are partially trusted, not silently promoted to trusted. Trusted dependencies are named by role and compromise assumptions. Map F01–F12 exactly once; F13/F14 remain bookkeeping/design-evidence risks, not security threats unless a concrete impact is demonstrated.
**Code Guidance:** Use compact Mermaid data-flow diagrams plus tables; diagrams do not replace textual trust transitions. Include misuse resistance for caller-supplied time, actor, authorizer, descriptor digest, dual-control choice, replay store and in-memory production presets. Include multi-tenant, multi-process, restart, stale-worker and malicious-persisted-payload cases. Do not copy audit API/DDL sketches as decided mitigations.
**Validation:** Contract contains all three trust classes, all named data flows and a threat row for every F01–F12 owner; scriptable check proves unique `TM-###` IDs, no `mitigated` row lacks evidence, every open threat has exactly one owning phase P2–P10, and terms `exactly-once`/`secure` occur only with explicit scope/negation; review against both PHP and Dart call boundaries finds no unexplained semantic difference.
**Deliverables:** `threat-model-v1.md` with assets, trust boundaries, data flows, threat/misuse catalog, owner mapping, proof expectations and residual-risk register.
