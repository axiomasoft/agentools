### P1.3 — Определить compatibility/support policy и migration inventory

**Intent:** Зафиксировать dated compatibility/support contract для spec, PHP, Dart, MCP и package consumers, а также inventory всех ожидаемых breaking/migration surfaces P2–P10.
**Why:** Текущие manifests декларируют PHP `>=8.3`, Dart `^3.11.0`, spec `2026-08` и private package identity, но единого контракта «declared vs tested vs release-supported» нет. SemVer требует сначала объявить public API; pre-1.0 не разрешает молчаливую миграцию. `RAG:—` (manifests/baseline); `RAG:✅` (`research/P1-design-rag.md`).
**Scope Included:** Matrix of package/spec/MCP/platform/dependency dimensions with `declared`, `observed`, `tested`, `release-supported`, `unsupported`; dated PHP/Dart floors; pre-1.0 change policy; schema/API/data/token/key/storage/fixture migration classes; compatibility test owner; consumer notification map; deprecation/removal decision points.
**Scope Excluded:** Declaring a platform supported without a green lane; choosing public license/registry; removing symbols; designing storage migrations; promising backward compatibility for accidental current exports.

**Implementation Rules:** Support is a tuple `(artifact version, spec revision, platform/dependency range, evidence date)`, never a bare version list. `release-supported` requires a named green CI/consumer carrier; absent lanes remain `declared` or `observed`. Current broad PHP PSR-4 and Dart barrel reachability are candidate surface only until P7. Every migration row has owner, compatibility risk, source/target shape, evidence needed, consumer and notification trigger. No migration writes occur in P1.
**Code Guidance:** Keep one matrix owner and link to it from migration inventory. Include current MCP release pin separately from Agentools spec revision and own conformance scope. Name Composer lowest/highest and `dart pub downgrade` lanes as future P9 proof carriers, not completed evidence. Explicitly state how 0.x breakage is documented and when 1.0 stability begins.
**Validation:** Every declared manifest constraint appears in the matrix; every `release-supported` cell links to a baseline/CI receipt; every accepted audit finding that can change API/data/token/storage/package shape has exactly one migration-inventory row and P2–P10 owner; public identity remains `private/proprietary`; no unqualified `MCP compliant`, `all versions`, `backward compatible` or `stable API` claim remains.
**Deliverables:** Versioned compatibility/support policy and complete migration/consumer-notification inventory suitable as inputs to P2–P10 and the final release dossier.
