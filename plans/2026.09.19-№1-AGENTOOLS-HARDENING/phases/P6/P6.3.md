### P6.3 — Доказать JCS по pinned independent oracle и differential corpus

**Intent:** Расширить JCS gate до независимого RFC/upstream oracle, 10 000 deterministic number cases, UTF-16/Unicode/raw-invalid boundaries и byte-level PHP/Dart receipts.
**Why:** Current focused suites are green but mostly share a small golden corpus; two SDKs can agree on the same serialization defect, especially around IEEE-754 formatting and UTF-16 ordering. RFC 8785 defines those boundaries explicitly. `RAG:✅` in `research/P6-design-rag.md`.
**Scope Included:** Exact upstream commit/provenance/license; six upstream input/output/outhex cases; bounded 10k number corpus/checksum; PHP/Dart oracle drivers; UTF-16 BMP/non-BMP ordering; escaped controls; no Unicode normalization; raw duplicate/invalid surrogate/malformed-number cases; NaN/infinity rejection; byte-diff diagnostics; successor fixtures and deterministic report.
**Scope Excluded:** Treating PHP or Dart as oracle; network at test time; 100M-number mandatory gate; cryptographic algorithm redesign; event/token hash ownership; runtime Node dependency; changing RFC semantics to match an SDK; fuzz/mutation depth owned by P8.
**Inputs:** P6.1 canonicalization contract and successor corpus · current PHP/Dart canonicalizers/tests · RFC 8785 · `cyberphone/json-canonicalization` commit `19d51d7fe467d4706a3ff08adf8a748f29fc21e0` and Apache-2.0 license · D11.
**Files:** `conformance/oracles/jcs/**` · `fixtures/2026-09/golden/jcs/**` · `php/tests/Schema/CanonicalizerOracleTest.php` · `dart/agentools/test/schema/canonicalizer_oracle_test.dart` · `conformance/bin/jcs-differential` · `conformance/tests/JcsDifferentialTest.php` · `conformance/reports/jcs-parity.json` · `php/src/Schema/Canonicalizer.php` · `dart/agentools/lib/src/schema/canonicalizer.dart` · `dart/agentools/lib/src/schema/jcs_number.dart`.
**Required Reads:** 1) P6.1 canonicalization rules/cases 2) `plans/2026.09.19-№1-AGENTOOLS-HARDENING/research/P6-design.md` §3 and `plans/2026.09.19-№1-AGENTOOLS-HARDENING/research/P6-design-rag.md` 3) RFC 8785 sections 3.1–3.2 and appendices 4) pinned upstream testdata README, license, canonicalizer and numgen 5) current PHP/Dart canonicalizer source/tests 6) `fixtures/2026-08/golden/jcs/**` provenance.
**Implementation Rules:** Vendor only declared upstream files with path, commit, SHA-256 and license provenance. Expected bytes originate from the pinned oracle/RFC, never an SDK. The 10k corpus must match upstream checksum before use. Raw invalid cases reach `canonicalizeJson` without a parser normalizing duplicates first. Reports compare UTF-8 bytes and show first differing offset plus digests. No BOM/newline is added. Network is forbidden in normal validation. If an SDK cannot represent an I-JSON number exactly, reject before semantic hashing rather than round silently. 100M remains optional P8 evidence.
**Code Guidance:** Stream number cases to bound memory. Keep oracle data separate from product fixtures but copy digest-qualified expected rows into the successor corpus. Preserve negative raw bytes as files. A minimized failing case is diagnostic output, not an automatically rewritten golden.
**Validation:** All six upstream cases match expected bytes in PHP and Dart; first 10,000 number rows match checksum and both SDK outputs; UTF-16 ordering crosses BMP/non-BMP correctly; decomposed Unicode remains decomposed; duplicate names, malformed escapes/surrogates/numbers and non-finite programmatic values are rejected with the successor semantic code; byte-mutant and number-boundary mutant are red; offline rerun succeeds; full canonicalizer suites stay green; no runtime dependency changes; plan lint adds no ERROR.
**Deliverables:** Pinned licensed independent JCS oracle, bounded high-depth corpus, PHP/Dart byte-level receipts and deterministic mismatch report.
