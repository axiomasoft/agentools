### P8.4 — Доказать PostgreSQL invariants multi-process crash schedules

**Intent:** Выполнить versioned deterministic schedules против реального PostgreSQL через отдельные PHP/Dart worker processes и доказать replay, lease/fencing and EventStore invariants при blocking, rollback, crash, takeover and skew.
**Why:** Two connections in one test process prove базовую arbitration, но не гарантируют, что gates различают blocked backend, killed client, stale worker and ambiguous post-commit result. Sleeps and SQLite cannot establish those states. `RAG:✅` PostgreSQL semantics in `research/P8-design-rag.md`.
**Scope Included:** Language-neutral schedule DSL; controller/worker line protocol; one physical connection per actor; application-name/PID observation; explicit IPC barriers; `pg_stat_activity`/`pg_blocking_pids` evidence; bounded lock/statement timeouts; client crash, query cancel and backend termination classes; consume commit/rollback races; lease takeover/stale CAS/clock-skew; event batch/version/collision/pagination schedules; invariant verifier and cleanup receipt.
**Scope Excluded:** Owner/production database; in-memory/SQLite substitute; sleep-based ordering proof; arbitrary network partition simulator; server/power-loss WAL certification; exactly-once external effect claim; CI service/container wiring; changing P3–P5 contracts to fit the harness.

**Implementation Rules:** Preflight accepts only an explicitly configured isolated test database, verifies its identity, creates a run-qualified namespace and deletes only that namespace. Every actor is a separate process and connection with `application_name=agentools-p8:<run>:<scenario>:<actor>`. Ordering comes from acknowledged controller barriers plus observed backend/lock state, never elapsed sleep. Receipt distinguishes `client_crash`, `query_cancel`, `backend_terminate` and normal rollback. Replay schedules cover conflicting uncommitted insert commit and rollback; lease schedules cover simultaneous acquire, expiry/takeover and stale heartbeat/complete/fail under the P4 clock contract; event schedules cover expected-version race, atomic batch rollback, identical replay, content collision, partial overlap and keyset pages. After every fault, a fresh verifier connection checks durable invariants. A failed upstream guarantee returns to its declared owner; P8 does not weaken it.
**Code Guidance:** Use structured JSON-lines over pipes/sockets, process groups and bounded teardown. Discover worker PIDs through acknowledgements and PostgreSQL backend PIDs through the connection; observe waits with `pg_stat_activity` and blockers with `pg_blocking_pids`. Set `lock_timeout`, `statement_timeout` and `idle_in_transaction_session_timeout` for bounded failure, not latency evidence. Capture SQLSTATE and durable row digests without token/result/event secrets. Test clearly-before/after expiry and declared skew bounds; do not assert sub-millisecond wall-clock edges.
**Validation:** Safety preflight rejects non-test/ambiguous DSN and cleanup cannot cross the run namespace; no schedule file contains a sleep step; same schedule/seed yields the same acknowledged trace; replay commit/rollback races preserve exactly the P3 contract; one lease owner/takeover token wins and every stale CAS fails; event batch is all-or-nothing and replay/collision/partial-overlap classifications remain exact; observed blocked edges match expected `pg_blocking_pids`; killed worker leaves no committed partial state and post-commit ambiguity is reconciled from fresh durable state; PHP and Dart workers produce equivalent invariant sets; injected unfenced/non-atomic mutants turn schedules red; plan lint adds no ERROR.
**Deliverables:** Deterministic PostgreSQL schedule corpus, safe multi-process controller/workers, crash/concurrency traces and digest-bound replay/lease/event invariant receipt.
