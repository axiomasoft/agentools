### P5.1 — Заморозить EventStore/audit/observability contract, collision/redaction и adversarial cases

**Intent:** Выпустить versioned P5 contract, который задаёт uncommitted/committed envelopes, atomic batch append, storage-assigned seq/global_position, content-hash collision vs identical replay vs partial overlap, keyset pagination, audit allow/deny, metric cardinality, snapshot provenance и общий набор PHP/Dart adversarial cases.
**Why:** Current ports append one caller-assembled `ActionEvent`; duplicate `event_id` is a silent no-op; `readFrom` has no limit. F05 is confirmed. Audit SQL/`EventStore` sketches are not the schema (F14). `RAG:—`; внешние ограничения — `research/P5-design-rag.md`.
**Scope Included:** Stream identity `(tenant_id, action_id)`; expected_prev_seq=0 empty stream; UncommittedEvent vs committed ALC-5 `ActionEvent`; hash exclusions; batch/page bounds; classify-before-INSERT algorithm; audit payload allow/deny; closed metric labels; snapshot `seq`+`spec_rev`+content hash; PHP/Dart migration of `EventLog.append(ActionEvent)`; machine-readable positive/negative case IDs.

**Implementation Rules:** Contract distinguishes uncommitted write DTO from committed ALC-5 envelope. Storage assigns `seq` and `global_position`; callers never supply them. Content hash excludes those fields plus `expected_prev_seq` and `prev_hash`. Identical suffix replay is success; different hash is collision; partial overlap is conflict; empty/`Any` expected-version modes do not exist. Audit events share the journal. Snapshot never truncates the log. Frozen `2026-08` remains byte-identical. Numeric bounds match `research/P5-design.md`. Single-event `EventLog.append(ActionEvent)` is unsupported after cutover; dual uncommitted+caller-seq production append is forbidden.
**Code Guidance:** Manifest `schema_version=event-store-cases/v1` has unique case IDs, phase (`append|load|collision|replay|pagination|audit|metrics|snapshot`), expected semantic code/category, PHP/Dart applicability and named seam. Include at least: 50-way append one winner; atomic two-event batch rollback; identical replay; payload collision; partial overlap; duplicate id in batch; empty batch; page abut/no-skip; limit>1000 reject; secret/PII audit reject; metric label deny tenant/action; snapshot hash mismatch discard; seq-derived event_id reject. Migration inventory names every `EventLog`/`append(ActionEvent)` consumer and one P5/P6/P7 disposition.
