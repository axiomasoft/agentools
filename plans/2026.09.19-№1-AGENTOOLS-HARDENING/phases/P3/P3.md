# P3 — Durable anti-replay, token envelope и key lifecycle

## Phase Context

P3 заменяет process-local spent-token set атомарным durable consume и вводит versioned,
bounded, purpose-separated token envelope с key rotation. Порядок consume/outcome закрепляется
как security policy: погашение есть свойство предъявления (CNF-20), а не успеха authorization.

> **Контракт фазы (contract-first).** Потребляет: P1 threat/guarantee/resource contracts и P2
> binding tuple / ConfirmationService ports. Производит: token-replay contract, PHP/Dart codec и
> key provider, consume port, PostgreSQL adapter, cleanup/retention и wiring в supported path.
> Границы: idempotency execution records — P4; event journal — P5; shared spec/error revision —
> P6; final exports — P7; mutation/fuzz depth — P8.

> **Phase Assurance | v1.**
> Impact: security-external
> Integration Seams: token-codec · key-provider · replay-store · postgresql-pdo · confirmation-service
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: crash/restart/two-process tests, parser mutations и key-rotation vectors доказывают
> security semantics; Review=full.

## Scope Included

Envelope version/algorithm allowlist/key id/issuer/audience/token id/tenant/purpose/proposal/binding
claims; signature verification; duplicate-key/size/depth rejection; purpose/tenant key separation;
active/verify-only/compromised/retired lifecycle; atomic consume API and adapter; outcome, expiry and
safe digest; cleanup/retention; multi-process and restart tests; PHP/Dart semantic vectors.

## Scope Excluded

JWT as a requirement; arbitrary crypto invention; external KMS product integration beyond a port;
idempotency lease records; event-store durability; editing `spec/revisions/2026-08/**`; final package
split; public release; exactly-once external tool effect; live owner-database migration.
