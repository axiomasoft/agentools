### P3.2 — Ввести bounded at1 codec и TokenKeyProvider в PHP/Dart

**Intent:** Добавить в оба SDK семантически одинаковые versioned codec, canonical signing input и tenant/purpose key provider без durable store.
**Why:** Current `ConfirmationToken` MAC-подписывает unordered JSON без `kid`/`iss`/`aud`/`jti` и принимает любой `TokenSigner`; duplicate names and oversize input are not rejected. `RAG:—`.
**Scope Included:** `at1` issue/parse; canonical flat JSON signing input; closed claim objects; `TokenKeyProvider` and key states; HS256 with ≥32-byte CSPRNG key; constant-time verify; PHP/Dart parser and key-isolation tests driven by the P3.1 manifest.
**Scope Excluded:** PostgreSQL adapter; ConfirmationService wiring; package export removal; changing frozen schemas; JCS oracle ownership (P6 may later certify the local profile); KMS.

**Implementation Rules:** Decode size-checks the raw string first. Parser rejects duplicate names without relying on `json_decode`/`jsonDecode` last-wins. Signing input is compact UTF-8 JSON with lexicographically sorted keys and no insignificant whitespace; PHP and Dart must byte-match. `alg` in the payload must equal the verification key's single algorithm. `verify_only` keys cannot sign. `compromised`/`retired` and unknown kid deny. `TokenSigner` remains a deprecated one-key adapter for tests, not the supported production port. No production in-memory key ring that shares secrets across tenants.
**Code Guidance:** Do not put raw tokens, secrets, jti or tenant IDs in exception messages. Prefer ULID/CSPRNG for `jti`. Keep payload flat; do not wrap claims in a JOSE header. Test fakes live only in test files. Existing fixture `at1.eyJ2IjoxfQ.Zm9vYmFy` is spec illustration, not a valid v1 token.
