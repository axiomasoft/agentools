**Intent:** Ввести в оба SDK порт atomic consume с PostgreSQL adapter на injected SQL и retention cleanup, который нельзя обойти in-memory preset.
**Why:** Unique `(tenant_id, jti)` claim is the only proof of CNF-20 across workers. Process-local sets and success-only writes leave restart and concurrent holes. `RAG:—`; SQL semantics — `research/P3-design-rag.md`.
**Scope Included:** `ConfirmationTokenStore.consume` / outcome refine / cleanup; versioned SQL schema; PHP PDO PostgreSQL adapter; Dart adapter over injected SQL executor; testkit in-memory store clearly marked non-production; concurrency, restart, cleanup and collision tests.
**Scope Excluded:** ConfirmationService public API; codec field changes; event journal; idempotency leases; adding Composer/pub driver libraries; applying SQL to an owner production database; CI matrix ownership (P9).

**Implementation Rules:** `consume` executes `INSERT ... ON CONFLICT (tenant_id, token_id) DO NOTHING RETURNING token_id` inside the caller transaction if one exists. Empty RETURNING is spent; do not SELECT-after-empty to authorize an effect. Outcome starts as `presented` and may be updated once to `authorized|authorization_denied|policy_denied`; UPDATE must not delete the row. Cleanup is `DELETE WHERE expires_at + retention < :now` using the injected clock; unexpired rows must survive. Partial unique indexes on unexpired rows are forbidden. In-memory implementation lives under test/reference namespaces and cannot be the default production constructor. PHP `suggests` `ext-pdo_pgsql`; Dart does not add a `postgres` dependency. Item cannot close on in-memory evidence alone: PostgreSQL suite is mandatory.
**Code Guidance:** Shared SQL file is the schema SSOT. Store raw `token_digest` as bytea/hex, never log it. Tenant isolation is part of the primary key, not an application-only WHERE. Two connections/executors in one test process are sufficient to prove the arbiter; a restart test opens a new store instance on the same database.
**Validation:** Shared SQL applied to ephemeral PostgreSQL; two concurrent consume calls yield exactly one winner; restart denies the winner; jti collision with different digest does not overwrite; cleanup negative test fails if it deletes unexpired rows; PHPUnit postgres group and Dart SQL tests green; in-memory tests exist but a receipt records they are non-production; `cd php && composer analyse`; `cd dart/agentools && dart analyze`; `git diff --exit-code -- spec/revisions/2026-08`; plan lint adds no ERROR.
**Deliverables:** Durable consume port, PostgreSQL adapter, versioned SQL, cleanup, and concurrency/restart evidence.
