### P7.1 — Заморозить package-boundary contract и target API manifests

**Intent:** Создать один normative package-boundary contract и machine-readable target roster для PHP core, Dart core/testkit и Dart MCP companion, классифицировав каждый текущий symbol/export до переносов.
**Why:** PHP PSR-4 сейчас делает достижимыми все `AgenTools\\**` и `AgenTools\\Reference\\**`, а Dart main barrel реэкспортирует in-memory/fixed implementations; reachability не является осознанным stability promise. `RAG:—`.
**Scope Included:** Deterministic current inventories from Composer classmap/PSR-4 and transitive Dart exports; target classifications `stable`, `advanced`, `testkit`, `reference`, `internal`; package/import/symbol identity; production consumer and behavioural-test proof; introduced/deprecated/replacement metadata; cross-tier dependency rules; archive role; P1 migration/guarantee and P6 semantic links; complete delta disposition.
**Scope Excluded:** Moving source; changing manifests/exports; declaring a symbol stable without a production consumer; public registry/license decisions; inventing P2–P6 API before predecessor execution; automatic source generation.
**Inputs:** P1.1 API/archive baseline · P1.3 compatibility policy and migration inventory · P1.4 guarantees · P6.5 semantic manifest/residual receipt · current `php/composer.json`, PHP source/reference tree, Dart pubspecs/barrels and package consumers · D12.
**Files:** `plans/2026.09.19-№1-AGENTOOLS-HARDENING/root/contracts/package-boundary-v1.md` · `api/package-surface-v1.json` · `tools/package_surface.py` · `plans/2026.09.19-№1-AGENTOOLS-HARDENING/findings/P7-api-inventory.md`.
**Required Reads:** 1) P1.1 baseline and P1.3/P1.4 terminal contracts 2) P6.5 semantic manifest/residual receipt 3) `plans/2026.09.19-№1-AGENTOOLS-HARDENING/research/P7-design.md` and `plans/2026.09.19-№1-AGENTOOLS-HARDENING/research/P7-design-rag.md` 4) `plans/AGENTOOLS/root/contracts/package-quality-baseline.md` 5) PHP/Dart manifests and all public barrels 6) current production/reference/test consumers 7) D12.
**Implementation Rules:** `package-boundary-v1.md` owns taxonomy and dependency rules; `api/package-surface-v1.json` owns the exact target entries, never a second handwritten Markdown list. Every reachable current entry has exactly one target disposition and evidence. `stable` requires an explicit package export/autoload classification, one production consumer and one behavioural test. Candidate reachability may become internal/testkit only when no stable evidence exists and P1 compatibility permits it; a proved stable removal needs a compatibility shim/deprecation or a new finite owner-gate. Tool output is deterministic, sorted, source-digested and separates `current`, `target`, and `delta`.
**Code Guidance:** Implement `inventory`, `validate-contract`, and `diff --actual` subcommands using stdlib only. PHP discovery reads Composer metadata plus tokenized declarations and fails on ambiguous FQNs; Dart discovery resolves export graphs including `show`/`hide` and cycles without treating direct `lib/src` imports as supported API. Cross-tier graph rejects core→testkit/reference/optional-adapter edges. Do not infer stability from visibility alone.
**Validation:** `python3 -m py_compile tools/package_surface.py`; focused tests cover alias/collision, export cycle, show/hide, undeclared extra, missing target, stable-without-consumer and forbidden tier edge; inventory reproduces P1 baseline or explains every digest delta; contract has zero unclassified reachable entries and zero duplicate identities; removing one target entry and adding one undeclared export each makes validation red; no P2–P6 semantic row changes.
**Deliverables:** Versioned boundary policy, exact target package-surface contract, deterministic inventory/diff tool and repository-grounded current→target migration report.
