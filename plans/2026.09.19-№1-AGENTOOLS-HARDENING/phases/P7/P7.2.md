### P7.2 — Отделить PHP core от testkit/reference и закрыть API drift

**Intent:** Привести Composer autoload, namespaces, archive contents и PHP docs/tests к P7.1 contract: production dependency получает только core, а test doubles/reference slice доступны только development root.
**Why:** `php/composer.json` помещает `AgenTools\\Reference\\` в production `autoload`, а `InMemory*`/`FixedClock` лежат в `src`; optimized consumer autoload therefore cannot distinguish production contract from examples/testkit. `RAG:—`.
**Scope Included:** Stable/advanced PHP namespace allowlist; Composer production vs `autoload-dev`; `AgenTools\\TestKit\\` and `AgenTools\\Reference\\` placement; in-memory/fixed/reference implementations; production dependency graph; package archive exclusions; `API.md` and migration examples; actual-vs-target manifest and behavioural consumer tests.
**Scope Excluded:** Changing safe confirmation, replay, lease, EventStore or semantic behavior; adding framework adapters; designing production databases; Packagist metadata/upload; deleting a proved stable symbol without authorized compatibility path; unrelated source layout cleanup.
**Inputs:** P7.1 contract/target/inventory · executed P2–P6 PHP surface and tests · P1 compatibility/migration policy · `php/composer.json`, `php/src/**`, `php/reference/**`, `php/tests/**`, `php/conformance/**` · D12.
**Files:** `php/composer.json` · `php/src/**` · `php/testkit/**` · `php/reference/**` · `php/tests/**` · `php/conformance/**` · `php/bin/**` · `php/API.md` · `php/UPGRADING.md` · `api/package-surface-v1.json`.
**Required Reads:** 1) P7.1 deliverables 2) P1 compatibility/migration contract 3) P2.4/P3.4/P4.4/P5.4/P6.5 PHP receipts 4) Composer official schema sections `autoload`, `autoload-dev`, `archive` in `plans/2026.09.19-№1-AGENTOOLS-HARDENING/research/P7-design-rag.md` 5) current Composer manifest/lock and complete PHP source/reference/tests/conformance graph 6) D12.
**Implementation Rules:** Production `autoload` contains no `AgenTools\\Reference\\` or testkit mapping; dev-only mappings are root-only and archive-excluded. Process-local/in-memory/fixed implementations move to the testkit tier or remain only through an explicitly documented compatibility shim allowed by the target contract; production services never instantiate them by default. `src` has no dependency on testkit/reference. Stable FQNs and signatures remain exact; candidate accidental names may move only with recorded disposition/migration. `composer.lock` changes only if manifest resolution requires it and no new runtime package is introduced.
**Code Guidance:** Preserve behavior while changing ownership. Use namespaces/Composer mappings rather than runtime environment switches. Keep conformance/reference entrypoints runnable from the repository development root, but prove that `composer install --no-dev --classmap-authoritative` in a clean consumer cannot autoload testkit/reference. Generated actual manifest comes from `tools/package_surface.py`; never hand-edit it to match source.
**Validation:** `composer validate --strict` in `php/`; `composer dump-autoload --no-dev --classmap-authoritative`; PHP unit/static analysis and P6 successor conformance green; target-vs-actual PHP surface exact; core→testkit/reference dependency edges zero; negative clean autoload probes for one testkit and one reference FQN fail while every stable FQN loads; archive listing contains required runtime/docs and excludes `tests/`, `reference/`, `testkit/`, conformance internals and caches; migration snippets compile; an undeclared public FQN mutant makes the surface gate red.
**Deliverables:** Intentional PHP stable/advanced surface, dev-only testkit/reference contour, production-clean Composer archive policy, migration guide and exact API-drift evidence.
