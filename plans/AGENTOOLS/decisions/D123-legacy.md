## Решение

**Потребитель нормированного `--out` внесён в оба гейт-item'а SDK: P7.12 зовёт `conformance/bin/levels out/php-all.json --out conformance/reports/php-levels.md --write` / `--check`, P8.13 — то же с `out/dart-all.json` → `conformance/reports/dart-levels.md`; оба отчёта КОММИТЯТСЯ и стоят в `Files` своих items.** D118 нормировал параметр у ПРОИЗВОДИТЕЛЯ (P6.9), но ни `Scope`, ни `Files`, ни `Validation` потребителей его не звали, а `Scope` (д)/(з) требовал «отчёт по уровням даёт долю прохождения» без указания, кто и куда его пишет. Добавлены три доказывающих прогона на каждой стороне: `--check` (отчёт производный и детерминированный), `git status --short` по ЧУЖИМ отчётам = пусто (`--out` действительно развёл потребителей), `git ls-files --error-unmatch` по своему (отчёт закоммичен, а не остался в игнорируемом `out/`). Альтернатива «оставить как есть, исполнитель догадается» отклонена фактом штатных исходов: без пути в `Files` исполнитель либо пишет файл ВНЕ `Files` (материальный триггер `plan-protocol` §6 — гейт-item фазы закрывается `🟠` из-за оформления), либо считает уровень из `out/*.json` и объявляет его без коммитимого производного артефакта — то есть заявленный уровень, на котором стоят Q-15/Q-17 и фазы P9/P10, воспроизвести нечем. If-then-ветки Code Guidance обоих items («`bin/levels` не принимает путь параметром → `🔴` с адресатом P6.9») СОХРАНЕНЫ как fail-safe: они срабатывают ровно в случае, когда фаза P6 закрылась вопреки D118
