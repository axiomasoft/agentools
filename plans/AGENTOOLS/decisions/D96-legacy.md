## Решение

**Фаза P8 оркестрацию НЕ объявляет — критерий `plan-protocol` §7 перепроверен ПОСТРОЧНО по фактам items** (не унаследован от вердиктов фаз P4/P6/P7). Сигнал 1 не срабатывает дважды: по данным — двенадцать items из тринадцати ссылаются `Inputs` на `Deliverables` предшествующих items ТОЙ ЖЕ фазы (канон запрещает это буквально), по scope — те же двенадцать пишут в ОДИН пакет `dart/agentools/**` с общим манифестом, общим `analysis_options.yaml` и общим прогоном `dart analyze`; единственный физически независимый item (P8.12 — отдельный пакет) не даёт требуемого «N≥3». Сигнал 2 не срабатывает: каждый item строит публичную поверхность pub-пакета, который реализует чужая кодовая база (`axioma_assistant`/`axioma_mcp`), то есть класс `Review=full`, для которого инвариант D6 `plan-protocol` §9 ЗАПРЕЩАЕТ поток «без подтверждения между items»; плюс P8.12 несёт развилку, разрешаемую на дату исполнения, — автономная цепочка через неё не проходит по построению. Альтернатива «оркестровать P8.12 параллельно с P8.5–P8.11» отклонена: выигрыш один item против сериализующей топологии закрытия (item-коммит на item) — отрицательный, тот же довод, что D35/D74/D84

## Почему

`plan-protocol` §7 (критерий + «a workflow is NOT set up just in case») и §9 (D6-инвариант); узкое место фазы — точность второго прочтения замороженной семантики и совпадение межъязыковых величин, а не пропускная способность записи файлов. `RAG:— (repo-grounded: research/07-p8-dart-sdk-2026-08.md §10; phases/P8.md — Inputs items P8.2–P8.13)`
