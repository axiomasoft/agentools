## Решение

**Механика freeze — жёсткий порядок шести шагов** (GREEN → owner-гейт → предфриз-проверки → флип статуса README → аннотированный тег `spec-2026-08` → `## 7. Contracts`), перестановка запрещена: тег на дереве с несвежим производным артефактом замораживает расхождение и делает слой 2 гейта CI ложно-зелёным. Статус ревизии — РОВНО ОДИН носитель в README (`**Статус:** frozen`; при иной форме, записанной P3.1, строка нормализуется item'ом P5.2); каталог не переименовывается (D19, anti-regression №7); тег только аннотированный, перезапись запрещена; якорь lockstep (`DR-01` §J8) = имя каталога = имя тега, CI-сверка манифестов SDK — граница фазы P6. Альтернатива «lightweight-тег» отклонена: тег — носитель провенанса freeze, а не метка

## Почему

свежесть проверяется по ТРЁМ производным артефактам (D43 + D58: `rules.json`, `schema/authoring/**`, `coverage.md`); запрет второго носителя статуса — тот же принцип, которым D41 запретил уровни правил отдельной таблицей. `RAG:— (repo-grounded: plan.md §5 D19, D41, D43, D58; research/04-p5-audit-gate-2026-08.md §7)`
