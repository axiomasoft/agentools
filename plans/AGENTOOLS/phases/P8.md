# P8 — Dart SDK `agentools` — зелёный на тех же векторах

## Phase Context

Третья фаза волны реализации и **вторая нативная реализация** ревизии `2026-08` (метка `DR-01` §K —
«P3 Dart SDK»; прежний номер фазы — P3, см. карту переименования `plan.md` §4). Pub-пакет
`agentools` — pure Dart, без Flutter-зависимостей: контракты и порты, value objects с валидацией и
СОБСТВЕННОЙ канонизацией JCS, идентичность расширения, профиль инструмента, журнал действия, реестр
эффектов, подтверждение, идемпотентность, ошибки, сценарии, длинные операции, аудит, безопасность.
Персистентность — контракты + in-memory реализации (D13). Зеркалит модульную раскладку PHP SDK
(фаза P7 — референс решений), но пишется идиоматичным Dart, а **не транслитом**: планка фазы —
зелёный прогон **тех же** векторов, и именно независимость второго прочтения делает этот прогон
защитой от дрейфа, а не сравнением копии с оригиналом.

**Транспорт живёт в ОТДЕЛЬНОМ пакете-спутнике** `dart/agentools_mcp_dart/` (D86, решение владельца
2026-07-27): ядро несёт только порт `McpTransport`, реализация на `mcp_dart` — рядом. Довод
физический, а не вкусовой: гейт выхода фазы транспорт не затрагивает вовсе (harness-протокол —
построчный JSON по stdio, `DR-01` §J1; реальные LLM и сеть в conformance запрещены, D8; время —
через порт `Clock`), поэтому prerelease-зависимость иначе попала бы в пакет, чья гейтованная
поверхность её не использует ни в одном векторе.

**Item P8.12 обязан снять два долга разом.** (1) Триггер **T-1** `DR-02` §7 — подтвердить наличие
stable-релиза `mcp_dart` с той же поддержкой modern-эры ЛИБО явно принять риск prerelease-API;
разведка 2026-07-27 показала, что ветка «уйти на stable» не просто недоступна, а **опасна**: в
stable 2.2.2 нет НИ `McpProtocol.require2026`, НИ энфорсмента `resultType` (проверено грепом по
исходникам обеих версий — `findings/P8-…` §5), то есть переход по номеру версии потерял бы обе
возможности. (2) Находку **F7** аудита фазы P2 (D52): утверждение «`resultType` энфорсится
клиентом» перенесено в D39 как эмпирическое, но лога упавшего прогона в item-коммите `4344265`
нет, а единственная видимая в НАШЕМ коде проверка — рукописная, в тонком прототипе
(`bakeoff/dart-transport/client-thin/main.dart:38`). Разведка нашла энфорсмент в библиотеке
(`mcp_dart-2.3.0-dev.3/lib/src/shared/protocol.dart:790`), но это пересчёт на машине дизайнера —
D52 требует **закоммиченный** лог отрицательного прогона на дереве фазы.

**Несущая граница фазы: P8 РЕАЛИЗУЕТ, но не нормирует, не переиспользует эталон и не транслитерирует
PHP.** К её старту заморожены текст ревизии и схемы (P3 + freeze P5.2), корпус `fixtures/2026-08/**`
(P4), раннер и harness-протокол (P6), публичная семантика PHP SDK (P7). Расхождение «написано ↔
реализуемо» — дефект ревизии либо корпуса с ценой «новая датированная ревизия» (D19/D62/D72), а не
повод поправить по месту: `🔴 Blocked` + эскалация с названной ценой. Зато диагностика богаче, чем
у P7: доступны ТРИ независимых прочтения правила — красный на Dart при зелёных эталоне и PHP ⇒
виноват Dart; красный на обоих SDK при зелёном эталоне ⇒ разбор, адресат может быть и P6; красный
на всех трёх ⇒ подозрение на вектор либо текст правила; зелёный на Dart и красный на PHP ⇒ дефект
PHP SDK, адресат — фаза P7, фаза P8 его НЕ чинит. Все три вывода приводятся в отчёте. Полный
разбор — синтез `research/07-p8-dart-sdk-2026-08.md` §2.

**Что фаза решает сама** — только форму НАШИХ пакетов, ревизией не нормируемую: раскладка
`dart/**` двумя сиблингами, состав портов, дом conformance-адаптера, механика lock и игнорирования,
констрейнты пинов, порог Dart SDK (D86–D93). Публичная поверхность пакета — новый носитель факта,
который в программе Axioma будет реализовывать чужая кодовая база.

**Status:** ⬜ Not started
**Intent:** Реализовать типы ревизии РУКАМИ по опубликованным схемам (вердикт `DR-02` §4), слой валидации сообщений против этих схем на пине `json_schema` 5.2.2 с ЯВНЫМ указанием драфта 2020-12, СОБСТВЕННУЮ реализацию канонизации JCS (`DR-01` §D4, `D15` — готового пакета в Dart нет) с явным перечнем инвариантов, и носитель «сырое сообщение сохраняется целиком» (§E3), на который опираются журнал и must-ignore.
**Why:** Это фундамент трёх межъязыковых инвариантов сразу: на канонизации стоят `descriptor_digest` (§B7), `args_fingerprint` (§D1) и хеш-цепочка журнала (§C7) — расхождение с PHP здесь обесценивает подтверждение, дедупликацию и аудит одновременно. В Dart цена выше, чем в PHP, по трём измеренным причинам. Первая: JCS пишется САМИМИ, то есть у нас нет даже спорного пина — ближайший кандидат `canonical_json` 1.1.3 реализует Canonical JSON проекта OLPC и ПРОТИВОРЕЧИТ §D4 в двух пунктах (требует Unicode NFC, запрещает числа с плавающей точкой), то есть взятый по имени дал бы зелёные тесты на целочисленных фикстурах и разошёлся бы с PHP на первом дробном числе. ### P8.5 — Журнал действия + контракты персистентности в Dart (§C1–§C3, §C5–§C7, D13)

### P8.9 — Ошибки и расширяемость в Dart: строковые коды, открытые перечисления, must-ignore (§E1–§E3, §E7)

**Status:** ⬜ Not started
**Intent:** Реализовать двухуровневую модель ошибок (protocol errors ↔ tool execution errors) со строковыми кодами в форме, близкой к RFC 7807, и запретом числового диапазона MCP; открытые перечисления как композицию известных значений + fallback-ветка; правило must-ignore с сохранением сырого события ЦЕЛИКОМ; жизненный цикл значений Active → Deprecated → Removed.
**Why:** Это место, где «работает» и «правильно» расходятся дальше всего. Числовые коды в диапазоне `-32000..-32099` запрещены не стилистически: `-32020..-32099` зарезервирован спекой MCP, и их использование уже вызывало перенумерацию в чужих SDK. Открытые перечисления существуют, чтобы добавление значения не было breaking-изменением автоматически, — и в Dart ловушка ОСТРЕЕ, чем в PHP: `enum` здесь настолько идиоматичен, а `switch` по нему настолько поощряется исчерпывающей проверкой компилятора, что «правильный» с точки зрения языка код автоматически делает добавление значения breaking-изменением.
