### P8.3 — Value objects, валидация против опубликованных схем, СОБСТВЕННАЯ JCS, raw-preserving

**Intent:** Реализовать типы ревизии РУКАМИ по опубликованным схемам (вердикт `DR-02` §4), слой валидации сообщений против этих схем на пине `json_schema` 5.2.2 с ЯВНЫМ указанием драфта 2020-12, СОБСТВЕННУЮ реализацию канонизации JCS (`DR-01` §D4, `D15` — готового пакета в Dart нет) с явным перечнем инвариантов, и носитель «сырое сообщение сохраняется целиком» (§E3), на который опираются журнал и must-ignore.
**Why:** Это фундамент трёх межъязыковых инвариантов сразу: на канонизации стоят `descriptor_digest` (§B7), `args_fingerprint` (§D1) и хеш-цепочка журнала (§C7) — расхождение с PHP здесь обесценивает подтверждение, дедупликацию и аудит одновременно. В Dart цена выше, чем в PHP, по трём измеренным причинам. Первая: JCS пишется САМИМИ, то есть у нас нет даже спорного пина — ближайший кандидат `canonical_json` 1.1.3 реализует Canonical JSON проекта OLPC и ПРОТИВОРЕЧИТ §D4 в двух пунктах (требует Unicode NFC, запрещает числа с плавающей точкой), то есть взятый по имени дал бы зелёные тесты на целочисленных фикстурах и разошёлся бы с PHP на первом дробном числе. Вторая: `String` в Dart — UTF-16, а §D4 прямо называет ключи вне BMP (суррогатные пары) известным местом расхождения реализаций, — в Dart это не теоретический риск. Третья: 2020-12 у `json_schema` НЕ является умолчанием (дефолт draft-7), и молчаливое умолчание означает валидацию ревизии по чужому драфту при полностью зелёном прогоне. `RAG:✅ 2026-07-27 (pub.dev/packages/canonical_json — 1.1.3, google.dev, Apache-2.0: реализует Canonical JSON проекта OLPC, ЗАПРЕЩАЕТ floating point, ТРЕБУЕТ Unicode NFC; реестр реализаций JCS cyberphone/json-canonicalization Dart не перечисляет)` · `RAG:✅ 2026-07-27 (pub.dev/packages/json_schema/changelog — поддержка Draft 2020-12 добавлена в 4.0.0 как SchemaVersion.draft2020_12; дефолт схемы — draft-7)` · `RAG:— (repo-grounded: DR-01 §D4 — JCS с перечнем инвариантов и ключами вне BMP, §E3 — сырое событие сохраняется целиком, §E5 — схемная гигиена и запрет сетевых $ref; DR-02 §4 — DTO руками, 87 строк на 3 типа при делегировании валидации json_schema; plan.md §5 D15; findings/P8-… §4, §7)`.
**Scope Included:** (а) value objects ядра по опубликованным схемам ревизии, написанные руками идиоматичным Dart (`final class`, неизменяемые поля, именованные параметры, `fromJson`/`toJson`), с ОБЯЗАТЕЛЬНЫМ правилом: множество полей типа совпадает с множеством `properties` соответствующей опубликованной схемы; (б) raw-preserving носитель: каждый разобранный документ сохраняет ИСХОДНУЮ `Map` целиком (не пересборкой поле-за-полем), `toJson()` возвращает её с наложенными изменениями — round-trip неизвестного свойства обязан быть побайтно точным; (в) слой валидации на `json_schema` 5.2.2: загрузка опубликованных схем ревизии с ЯВНЫМ `SchemaVersion.draft2020_12`, резолв относительных `$ref` ОФЛАЙН (сетевой `$ref` запрещён §E5 — у `json_schema` есть режим удалённой загрузки, он обязан быть выключен), сообщение об ошибке валидации несёт путь и правило; (г) **собственная реализация JCS** одним классом-фасадом `Canonicalizer` по инвариантам `DR-01` §D4: сортировка ключей по кодовым единицам UTF-16 согласно RFC 8785, ECMAScript-совместимая сериализация чисел, ОТКАЗ при `NaN`/`Infinity`, ОТКАЗ при дублирующихся ключах, НИКАКОЙ Unicode-нормализации; (д) **прогон официальных векторов RFC 8785** из upstream-набора как тест пакета — те же данные, что прогоняет P7.3; (е) **отдельный анти-NFC-тест**: строка в разложенной Unicode-форме переживает канонизацию БЕЗ изменения кодовых точек; (ж) **тест ключей вне BMP**: канонический выход на ключах с суррогатными парами побайтно равен выходу PHP SDK на том же входе (межъязыковой якорь, `research/07-…` §9); (з) тесты, чьи ожидания взяты из векторов корпуса и из официальных векторов JCS, с перечнем заимствованных `id` в Completion Notes.
**Scope Excluded:** дескриптор инструмента и `descriptor_digest` (P8.4 — он ПОЛЬЗУЕТСЯ канонизацией этого item'а); журнал (P8.5); открытые перечисления, коды ошибок и must-ignore как правило поведения (P8.9 — здесь только структурный носитель сырых данных); схемы авторинга `schema/authoring/**` (предмет линтера спеки, не SDK); генерация типов любым инструментом (`DR-02` §4 — DTO руками); чекер структурной сверки «поле схемы ↔ поле типа» как артефакт слоя 2 CI (P8.13 при ветке (A) owner-gate; здесь — только само совпадение полей); ЛЮБЫЕ правки ревизии, схем, корпуса и PHP SDK.

**Implementation Rules:** множество полей каждого типа выводится из `properties` ЕГО схемы — расхождение является дефектом типа, а не «упрощением»; сохранение сырых данных делается ЦЕЛИКОМ (модель unknown fields протобуфа, §E3), пересборка поле-за-полем запрещена — именно она теряет неизвестное свойство; версия драфта указывается ЯВНО при загрузке КАЖДОЙ схемы (`SchemaVersion.draft2020_12`) — умолчание `json_schema` есть draft-7, и молчаливое умолчание валидирует ревизию по чужому драфту; режим удалённой загрузки `$ref` выключен явно (§E5), схемы читаются с диска ревизии; канонизация вызывается ТОЛЬКО через фасад `Canonicalizer` — прямые обходы `Map` в других модулях запрещены; собственная реализация JCS пишется ПО ТЕКСТУ RFC 8785 и §D4, а НЕ по коду `canonical_json` (его правила противоречат §D4 в двух пунктах — findings §7) и НЕ транслитом из `php/src/Schema/**`; официальные векторы RFC 8785 берутся из upstream-набора и коммитятся в `dart/agentools/test/` как ДАННЫЕ, их правка под реализацию — материальное отклонение; побайтная сверка с PHP делается против ЗОЛОТЫХ данных `php/tests/Schema/**`, литерал в Dart-тест не дублируется без записи в Completion Notes (правило единственного носителя, `research/07-…` §9); расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — прямое продолжение `bakeoff/dart/manual/*.dart` (замер 87 строк на 3 типа — принятая цена ручного пути, `DR-02` §4), идиоматичный Dart, НЕ транслит PHP. Канонизатор — чистая функция `String canonicalize(Object? value)` без состояния; числа сериализуются отдельной, отдельно протестированной функцией (это самая частая точка расхождения языков); работа со строками ведётся на уровне кодовых ЕДИНИЦ UTF-16 там, где так требует RFC 8785, и это комментируется «почему» — иначе следующий читатель «починит» на кодовые точки. Анти-самообман: «JCS написана» ≠ «JCS корректна» — доказательством считается ЗЕЛЁНЫЙ прогон официальных векторов RFC 8785, плюс три отрицательных (`NaN`, `Infinity`, дублирующийся ключ), плюс анти-NFC-тест, плюс побайтное совпадение с PHP на ключах вне BMP; «валидация работает» ≠ «валидация ловит» — нужен красный на заведомо невалидном документе И тест, доказывающий, что использован именно драфт 2020-12 (конструкция, которую draft-7 не понимает, обязана быть проверена). Анти-подгонка: если официальный вектор JCS не проходит — правится НАША реализация, вектор не трогается; если байты расходятся с PHP — разбирается ПРАВИЛО §D4 и обе реализации, а не подкручивается наша до совпадения (совпадение с ошибочным PHP хуже расхождения: оно молча замораживает дефект в обоих языках). ЗАПРЕЩЕНО: генерировать типы инструментом; брать `canonical_json` или любой пакет «канонического JSON» без побайтного прохождения векторов RFC 8785; вводить Unicode-нормализацию в любом виде; пересобирать документ поле-за-полем; вызывать канонизацию в обход фасада; резолвить сетевые `$ref`; загружать схему без явного указания драфта; править схемы ревизии, чтобы тип «сошёлся». If-then: собственная реализация JCS не проходит официальный вектор RFC 8785 и причина в САМОМ векторе (upstream-набор содержит кейс, противоречащий §D4) → `🔴 Blocked` + эскалация (trigger «конфликт правил») с адресатом «владелец»: расхождение нормативного текста ревизии с RFC — не выбор исполнителя. If-then: байтовый выход канонизации расходится с ЗОЛОТЫМИ данными PHP, и §D4 обе трактовки допускает → это недоспецифицированность с ценой «новая датированная ревизия»: `🔴 Blocked` + эскалация с адресатом «фаза P3 / владелец», в отчёте приводятся оба байтовых выхода и вход. If-then: опубликованная схема содержит ключевое слово, которого нет в Списке A `DR-02` §2, либо которое `json_schema` 5.2.2 не энфорсит → это дефект ревизии либо пина, а не повод расширить валидатор руками: `🔴 Blocked` + эскалация (trigger «конфликт правил»).
**Validation:** `dart analyze dart/agentools; echo $?` = 0 · `dart test --directory dart/agentools; echo $?` = 0 · прогон официальных векторов RFC 8785 зелёный, число прогнанных векторов напечатано и непусто (вывод — в Completion Notes) · три отрицательных прогона канонизации — `NaN`, `Infinity`, дублирующийся ключ — каждый отвергается с названной диагностикой (вывод — в Completion Notes) · анти-NFC-тест зелёный: строка в разложенной Unicode-форме проходит канонизацию БЕЗ изменения кодовых точек (вход, выход и их кодовые точки — в Completion Notes) · **межъязыковой якорь**: канонический выход на входе с ключами вне BMP побайтно равен золотому значению из `php/tests/Schema/**` — сверка выполнена КОМАНДОЙ (точная команда и оба значения — в Completion Notes; при невозможности прочитать золотое значение командой факт дублирования литерала называется явно) · round-trip неизвестного свойства побайтно точен: тест подаёт документ с ключом, которого нет ни в одной схеме, и сравнивает выход с входом — зелёный · валидация даёт КРАСНЫЙ на заведомо невалидном документе с указанием пути и правила (вывод — в Completion Notes) · тест драфта: конструкция 2020-12, не понимаемая draft-7, валидируется корректно — зелёный (какая именно конструкция — в Completion Notes) · `grep -rn 'SchemaVersion' dart/agentools/lib | grep -c 'draft2020_12'` ≥ 1 и `grep -rn 'SchemaVersion' dart/agentools/lib | grep -cv 'draft2020_12'` = 0 (другой драфт не используется нигде) · `grep -rn 'canonical_json\|normalize\|nfc\|NFC' dart/agentools/lib | wc -l` = 0 (чужой канонизатор и нормализация отсутствуют) · сверка множеств «поля типа ↔ properties схемы» по каждому реализованному типу печатает `OK` для всех (точная команда и вывод — в Completion Notes) · прогнать плановый линтер по каталогу плана и опубликовать счёт с атрибуцией, K = 0.
**Deliverables:** ручные value objects, множества полей которых доказанно совпадают с `properties` опубликованных схем + raw-preserving носитель с побайтным round-trip неизвестного свойства + слой валидации на `json_schema` 5.2.2 с ЯВНЫМ драфтом 2020-12 и офлайн-резолвом + СОБСТВЕННАЯ реализация JCS за единственным фасадом, доказанная официальными векторами RFC 8785, тремя отрицательными прогонами, анти-NFC-тестом и побайтным совпадением с PHP на ключах вне BMP.
