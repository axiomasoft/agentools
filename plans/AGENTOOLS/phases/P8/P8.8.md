### P8.8 — Идемпотентность в Dart: ключ + `args_fingerprint`, три состояния, два таймера (§D1–§D3)

**Intent:** Реализовать дедупликацию по документу `09` (правила `IDE-*`): клиентский идемпотентный ключ как ПЕРВИЧНЫЙ идентификатор, `args_fingerprint` как детектор misuse (но не первичный идентификатор), ровно три состояния записи без ожидания завершения параллельного запроса, два независимых таймера с РАЗНЫМИ кодами ошибок, порт `IdempotencyStore` с in-memory реализацией. `args_fingerprint` обязан совпасть с PHP на общих golden-входах.
**Why:** MCP не даёт механизма дедупликации вовсе — слой целиком наш, и в нём три ловушки, каждая из которых выглядит как разумное упрощение. Первая: считать ключ серверным хешом аргументов — ломается на легитимных повторах, где изменились несущественные поля (модель IETF-драфта и Stripe разводят ключ и fingerprint именно поэтому). Вторая: добавить четвёртое состояние «ждём завершения параллельного запроса» — драфт IETF и все три эталонных провайдера сходятся на НЕМЕДЛЕННОМ ответе, а ожидание превращает дедупликацию в распределённую блокировку; в Dart эта ловушка ближе, чем в PHP: `await` на завершение чужого `Future` выглядит идиоматично и естественно. Третья: слить два таймера в один — теряется защита от дубля после перезапуска клиента, потому что TTL токена подтверждения (минуты) и TTL записи дедупликации (часы–дни) выражают разный бизнес-риск. `RAG:— (repo-grounded: DR-01 §D1 — ключ генерирует вызывающий, fingerprint ловит misuse; §D2 — три состояния, ожидание запрещено, два разных кода ошибки; §D3 — два независимых таймера, второй ≥ первого + окно повторов; research/07-… §8, §9)`.
**Scope Included:** (а) клиентский идемпотентный ключ как первичный идентификатор записи; (б) `args_fingerprint` = хеш канонизированных аргументов через фасад P8.3 — ЕДИНСТВЕННЫЙ способ его посчитать в пакете; (в) три состояния и только три: `new` → выполнять; `duplicate-completed` → вернуть сохранённый результат КАК ЕСТЬ, включая сохранённую ошибку; `concurrent-in-flight` → немедленно вернуть конфликт; (г) два РАЗНЫХ кода ошибки: конфликт по времени (повторяемо позже) и тот же ключ с другими аргументами (ошибка вызывающего) — их слияние запрещено; (д) два независимых таймера: TTL токена подтверждения и TTL записи дедупликации, второй ≥ первого + окно клиентских повторов; значение задаётся по классу действия, а не константой в коде; (е) порт `IdempotencyStore` в `lib/src/contracts/` — минимальная поверхность, плюс in-memory реализация; (ж) **межъязыковой якорь**: `args_fingerprint` на общих golden-входах побайтно равен зафиксированному фазой P7 (`php/tests/Idempotency/**`); (з) тесты, чьи ожидания взяты из векторов `IDE-*`, с перечнем заимствованных `id`.
**Scope Excluded:** реестр эффектов и эпоха (P8.6 — другой механизм против другого дубля); токен подтверждения и его TTL как механика (P8.7 — здесь только соотношение таймеров); модель ошибок как таковая (P8.9 — здесь заводятся два конкретных кода в её форме); канонизация (P8.3); продуктовое хранилище записей дедупликации (D13 — вне репозитория); ЛЮБЫЕ правки ревизии, схем, корпуса и PHP SDK.

**Implementation Rules:** перечисление состояний ЗАКРЫТО тремя значениями (`enum`), четвёртое не заводится ни под каким именем — пока в перечислении есть «ждём», оно будет использовано (тот же довод, которым D71 закрыл перечисление статусов раннера); ожидание завершения параллельного запроса запрещено КОДОМ, а не соглашением: в модуле нет ни `await` на чужой `Future`/`Completer` завершения запроса, ни блокирующего цикла — проверяется грепом; `args_fingerprint` считается ТОЛЬКО через фасад канонизации P8.3 и сверяется с золотыми данными PHP; два таймера — два разных параметра с разными единицами конфигурации, соотношение «второй ≥ первого + окно повторов» проверяется тестом; сохранённая ошибка возвращается КАК ЕСТЬ, включая её код и тело — «переигрывать» её запрещено; расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как P8.5, идиоматичный Dart, НЕ транслит PHP; состояние — `sealed class` либо `enum` с исчерпывающим `switch` (компилятор обязан ловить забытую ветку). Анти-самообман: «дедупликация работает» ≠ «дедупликация различает три случая» — доказательством считаются три прогона: повтор завершённого возвращает сохранённый результат (в т.ч. ОШИБКУ), параллельный повтор отвечает НЕМЕДЛЕННО конфликтом, тот же ключ с другими аргументами даёт ОТДЕЛЬНЫЙ код. Анти-подгонка: если вектор ожидает немедленный конфликт, а реализация ждёт — убирается ожидание, а не смягчается вектор. ЗАПРЕЩЕНО: выводить ключ из аргументов на стороне SDK; заводить четвёртое состояние; ждать завершения параллельного запроса любым способом (`await`, `Completer`, `Future.any` по чужому запросу, polling); сливать два кода ошибок в один; сливать два таймера; считать fingerprint вторым способом. If-then: документ `09` не задаёт поведение при повторе с тем же ключом и теми же аргументами, но ИНЫМ инструментом → `🔴 Blocked` + эскалация (trigger «конфликт правил»). If-then: `args_fingerprint` не совпал с золотым значением PHP при зелёном P8.3 → `🔴 Blocked` + эскалация с адресатом «владелец + фазы P3/P7» (расходится СОСТАВ входа хеша, а не канонизация).
