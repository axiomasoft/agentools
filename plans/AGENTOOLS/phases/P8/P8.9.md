### P8.9 — Ошибки и расширяемость в Dart: строковые коды, открытые перечисления, must-ignore (§E1–§E3, §E7)

**Intent:** Реализовать двухуровневую модель ошибок (protocol errors ↔ tool execution errors) со строковыми кодами в форме, близкой к RFC 7807, и запретом числового диапазона MCP; открытые перечисления как композицию известных значений + fallback-ветка; правило must-ignore с сохранением сырого события ЦЕЛИКОМ; жизненный цикл значений Active → Deprecated → Removed.
**Why:** Это место, где «работает» и «правильно» расходятся дальше всего. Числовые коды в диапазоне `-32000..-32099` запрещены не стилистически: `-32020..-32099` зарезервирован спекой MCP, и их использование уже вызывало перенумерацию в чужих SDK. Открытые перечисления существуют, чтобы добавление значения не было breaking-изменением автоматически, — и в Dart ловушка ОСТРЕЕ, чем в PHP: `enum` здесь настолько идиоматичен, а `switch` по нему настолько поощряется исчерпывающей проверкой компилятора, что «правильный» с точки зрения языка код автоматически делает добавление значения breaking-изменением. Must-ignore MCP НЕ обязывает: ни JSON-RPC, ни ядро MCP не содержат явного MUST об игнорировании неизвестного, поэтому правило пишем мы — и код must-ignore протухает незамеченным именно потому, что в экосистеме из двух потребителей органических случаев расширения почти не бывает (урок IAB, отсюда GREASE-векторы §E4). `RAG:— (repo-grounded: DR-01 §E1 — два уровня ошибок, строковые коды, запрет диапазона MCP, форма RFC 7807; §E2 — oneOf из const + fallback-ветка с шаблоном; §E3 — сырое событие сохраняется целиком, пересборка поле-за-полем запрещена; §E4 — GREASE с первого релиза; §E7 — Active→Deprecated→Removed; research/07-… §8)`.
**Scope Included:** (а) двухуровневая модель: protocol errors (транспортные) и tool execution errors (бизнес/валидационные, возвращаются как результат с признаком ошибки и доступны модели для самокоррекции) — разведение по типам, а не по соглашению; (б) собственные коды — СТРОКОВЫЕ, в структурированном поле, форма объекта ошибки сближена с RFC 7807; числовые коды в `-32768..-32000` не используются вовсе; (в) открытые перечисления: разбор значения по известным вариантам плюс fallback по шаблону `^<product>\.[a-z0-9_]+$`, неизвестное значение НЕ отклоняется — носитель НЕ голый `enum`, а `sealed class` с ветвью `unknown(String raw)` либо эквивалент, сохраняющий сырое значение; (г) must-ignore (§E3) как правило поведения: неизвестный вид события, неизвестная категория ошибки, неизвестный ключ под нашим префиксом, неизвестное значение открытого перечисления — сообщение принимается И сырое событие сохраняется ЦЕЛИКОМ (носитель — raw-preserving слой P8.3); (д) жизненный цикл значений Active → Deprecated → Removed (§E7): депрецированное значение продолжает валидироваться, удалённое отвергается после окна; (е) прогон GREASE-векторов корпуса (§E4) как обязательное доказательство, с перечнем прогнанных `id`; (ж) тесты, чьи ожидания взяты из векторов `IDE-*`/`OVR-*`, покрывающих §E1–§E3, §E7.
**Scope Excluded:** конкретные коды других подсистем (`descriptor_drift` — P8.4, коды дедупликации — P8.8; здесь заводится ФОРМА, в которой они выражены); raw-preserving носитель как структура (P8.3 — здесь правило его применения); аудит (P8.11); продуктовые расширения `crm.*`/`erp.*` (§E2 — вне обязательного покрытия conformance); ЛЮБЫЕ правки ревизии, схем, корпуса и PHP SDK.

**Implementation Rules:** сохранение сырого события делается ЦЕЛИКОМ через носитель P8.3 — пересборка поле-за-полем запрещена (§E3: модель unknown fields протобуфа); открытое перечисление реализуется НЕ голым `enum`: известные значения + ветвь, сохраняющая сырое неизвестное значение, потому что голый `enum` с исчерпывающим `switch` делает добавление значения breaking-изменением автоматически — это НЕ стилистика, а §E2; числовые коды в диапазоне `-32768..-32000` не появляются в коде ни в каком виде — проверяется грепом; каждая tool execution error возвращается КАК РЕЗУЛЬТАТ с признаком ошибки, а не выбрасывается как исключение транспорта — иначе модель лишается самокоррекции; GREASE-векторы прогоняются раннером фазы P6 против ВРЕМЕННОГО тестового адаптера либо юнит-тестом на тех же данных — способ называется в Completion Notes явно; расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как `bakeoff/dart/manual/p01_open_enum.dart` (известные значения + сохранение сырого — это и есть §E2 в Dart). Анти-самообман: «must-ignore реализован» ≠ «неизвестное сохраняется» — доказательством считается ПОБАЙТНЫЙ round-trip документа с неизвестным ключом, а не «не упало»; «модель ошибок есть» ≠ «уровни разведены» — нужен тест, показывающий, что бизнес-ошибка возвращается результатом, а не исключением. Анти-подгонка: если GREASE-вектор красный, чинится must-ignore, а не «уточняется» вектор. ЗАПРЕЩЕНО: голый `enum` для открытых перечислений (включая `enum` с полем-строкой, у которого нет ветви неизвестного значения); числовые коды в зарезервированном диапазоне; пересборка документа поле-за-полем; отклонение сообщения из-за неизвестного значения; удаление значения из перечисления без окна депрекации; транслитерировать `php/src/Errors/**`. If-then: правило ревизии требует отклонить неизвестное значение там, где §E3 требует его игнорировать → это конфликт нормативного текста с решением: `🔴 Blocked` + эскалация (trigger «конфликт правил») с адресатом «владелец», реализация не выбирает сторону молча.
