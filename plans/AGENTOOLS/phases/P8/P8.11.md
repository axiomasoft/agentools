### P8.11 — Длинные операции, аудит и наблюдаемость, безопасность в Dart (документы `07`, `08`, `10`)

**Intent:** Реализовать три оставшихся документа ревизии: `07` (`LOP-*`) — длинные операции ОБОИМИ путями (поверх задачи MCP и синхронным вызовом без задач), немедленное журналирование идентификатора задачи, состояние «требует сверки», кооперативная отмена; `08` (`AOB-*`) — собственная схема аудита, поле корреляции, собственный подсчёт стоимости, непрозрачные идентификаторы baggage; `10` (`SEC-*`) — запрет проброса чужих токенов и различимая тройка принципалов в аудите.
**Why:** Каждый из трёх документов несёт правило, которое ломается тихо, и для Dart-контура цена выше, чем для PHP. §G1: расширение задач MCP — факультативная возможность контрагента, поэтому синхронный путь ОБЯЗАТЕЛЕН, и реализация «только через задачи» откажет ровно у offline-first контура Axioma, где расширения нет, — то есть у ГЛАВНОГО потребителя этого SDK. §G3: идентификатор задачи журналируется НЕМЕДЛЕННО, иначе падение между запуском и записью оставляет висящую задачу без владельца. §H2: долгий гейт не держит span — трассировка, ждущая человека, ломает бюджеты наблюдаемости. §I1: посредник, принимающий чужие токены, — классический confused deputy, и оба SDK архитектурно посредники. §I3: тройка принципалов различима без фиксации claim-схемы, потому что RFC 8693 и драфты делегирования для агентов ещё не ратифицированы. `RAG:— (repo-grounded: DR-01 §G1 — оба пути обязательны в conformance; §G2 — прогресс в процентах не обещать; §G3 — идентификатор задачи журналируется немедленно; §G4 — состояние «требует сверки»; §G5 — отмена кооперативная; §H1–§H5 — своя схема аудита, долгий гейт не держит span, поле корреляции, стоимость считаем сами, baggage непрозрачен; §I1 — запрет проброса токенов; §I3 — тройка принципалов без фиксации claim-схемы; open-questions.md Q-7; research/07-… §8)`.
**Scope Included:** (а) длинные операции ОБОИМИ путями (§G1): поверх расширения задач и синхронным вызовом без задач вовсе — оба пути реализованы и оба покрыты тестами; путь «поверх задач» выражен через ПОРТ, а не через `mcp_dart` (транспорт — другой пакет, P8.12); (б) немедленное журналирование идентификатора задачи (§G3), состояние «требует сверки» (§G4), кооперативная отмена (§G5) — отмена запрашивается, а не навязывается; (в) отсутствие обещания прогресса в процентах (§G2): поля процента в контракте нет — доказывается грепом; (г) собственная схема аудит-события (§H1) плюс ОПЦИОНАЛЬНЫЙ порт экспорта `AuditSink` — экспорт не обязателен и не тянет зависимость; (д) правило §H2: долгий гейт подтверждения не держит span наблюдаемости; (е) поле корреляции как ПОЛЕ, а не зависимость от трассировщика (§H3); собственный подсчёт стоимости (§H4); baggage — только непрозрачные идентификаторы (§H5); (ж) §I1: токен, выпущенный не для нас, не принимается — отдельный отказ с названной диагностикой; (з) §I3: каждая запись о действии агента несёт различимую тройку (конечный пользователь, агент как принципал, область действия на конкретный вызов) БЕЗ фиксации механизма токенов делегирования; (и) тесты, чьи ожидания взяты из векторов `LOP-*`/`AOB-*`/`SEC-*`, с перечнем заимствованных `id`.
**Scope Excluded:** событие решения по гейту §I4 (P8.7 — уже реализовано, здесь только не ломается); метка происхождения аргумента §I2 (P8.4); реальный экспорт в OTel/иную систему — только порт (§H1); реализация транспорта задач (P8.12 — здесь только порт); прогноз зрелости расширения задач MCP (остаток Q-7: conformance от неё не зависит по построению, прогноз фаза НЕ делает); реализация изоляции карантинного маршрута — дело рантайма (§I2); retention и хранилище аудита (§C7); ЛЮБЫЕ правки ревизии, схем, корпуса и PHP SDK.

**Implementation Rules:** ОБА пути длинной операции обязательны и оба тестируются — реализация «только через задачи» не сдана (§G1) и отказала бы у главного потребителя этого SDK; доступ к задачам выражается ПОРТОМ ядра, реализация транспорта живёт в пакете-спутнике (D86) — `mcp_dart` в ядре не появляется; идентификатор задачи пишется в журнал ДО первого ожидания, порядок проверяется тестом; отмена кооперативная — принудительного прерывания в коде нет (`Isolate.kill` и эквиваленты запрещены); поля прогресса в процентах в контракте нет (§G2) — отсутствие доказывается грепом; порт `AuditSink` ОПЦИОНАЛЕН: отсутствие реализации не ломает работу пакета и не тянет зависимость; поле корреляции — обычное поле, зависимости от трассировщика в пакете нет (§H3); baggage несёт только непрозрачные идентификаторы (§H5); чужой токен не принимается ни при каких условиях (§I1) — отдельный код отказа; тройка принципалов различима, но claim-схема НЕ фиксируется (§I3); расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как P8.5, идиоматичный Dart, НЕ транслит PHP; длинная операция — `Future`/`Stream` за портом, время — только через `Clock` (`Future.delayed` на системных часах в логике запрещён: он ломает виртуальное время conformance-адаптера). Анти-самообман: «длинные операции реализованы» ≠ «оба пути работают» — доказательством считается ПАРА прогонов: один и тот же сценарий поверх задачи и без задач вовсе, оба зелёные; «аудит есть» ≠ «аудит доказуем» — нужен тест, показывающий различимую тройку принципалов в записи. Анти-подгонка: если синхронный путь не сходится с вектором, чинится путь, а не объявляется «задачи обязательны» — это прямо запрещено §G1 и обесценило бы offline-контур.
