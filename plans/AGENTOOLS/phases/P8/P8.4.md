### P8.4 — Профиль инструмента: `descriptor_digest`, `descriptor_drift`, `content_origin` + межъязыковой якорь

**Intent:** Реализовать документ `02` (правила `TLP-*`): профиль контракта инструмента, вычисление `descriptor_digest` = SHA-256 канонической сериализации (`name` + `description` + `inputSchema` + `outputSchema` + блок расширения) по `DR-01` §B7, отдельный класс ошибки `descriptor_drift`, опциональное поле `content_origin: untrusted_external` (§I2) — и ВОСПРОИЗВЕСТИ ПОБАЙТНО золотое значение digest'а, зафиксированное фазой P7 (item P7.4).
**Why:** `DR-01` §B7 в разделе «Conformance» формулирует требование буквально: «Один и тот же дескриптор MUST давать байт-идентичный digest в PHP и Dart». Это ЕДИНСТВЕННОЕ место ревизии, где межъязыковой инвариант записан как норма, а не выводится, — и этот item является местом, где он либо доказывается, либо тихо не выполняется. Дескриптор — вход сразу двух подсистем: подтверждение сверяет digest на commit (анти-rug-pull, OWASP MCP03), аудит записывает его в решение по гейту; спрятанный внутри одного потребителя, он получает форму под него — поэтому вынесен в свой item, как и в P7. Отдельно `descriptor_drift` обязан быть ОТДЕЛЬНЫМ классом ошибки: слитый в generic auth/validation, он перестаёт быть сигналом подмены инструмента. `RAG:— (repo-grounded: DR-01 §B7 — состав digest, отдельный класс ошибки, требование байт-идентичности между языками; §I2 — content_origin как поле контракта; §B2 — descriptor_digest входит в покрытие токена; §E1 — форма строкового кода; research/07-… §8, §9; phases/P7.md P7.4 — золотое значение зафиксировано вместе с исходным дескриптором и помечено «межъязыковой якорь, фаза P8 обязана совпасть побайтно»)`.
**Scope Included:** (а) тип профиля инструмента по документу `02` и его схеме: состав полей берётся из ревизии; (б) вычисление `descriptor_digest` ТОЛЬКО через фасад канонизации P8.3 — состав входа и порядок берутся из правила ревизии; (в) **воспроизведение ЗОЛОТОГО значения P7.4**: тот же исходный дескриптор даёт тот же digest побайтно; исходный дескриптор и ожидаемое значение берутся из закоммиченных данных PHP-тестов, не переписываются «на глазок»; (г) сверка digest'а и `descriptor_drift` как ОТДЕЛЬНЫЙ класс ошибки в модели §E1 (строковый код), с диагностикой «что именно разошлось»; (д) метка происхождения аргумента `content_origin` как опциональное поле профиля (§I2): значение из открытого перечисления, отсутствие поля легально, неизвестное значение не отклоняется (§E2/§E3); (е) отрицательное доказательство пиннинга: правка `description` дескриптора МЕНЯЕТ digest, а commit со старым токеном даёт `descriptor_drift`, а не generic ошибку; (ж) тесты, чьи ожидания взяты из векторов корпуса, покрывающих `TLP-*`, с перечнем заимствованных `id`.
**Scope Excluded:** протокол подтверждения, токен, TTL, dual control (P8.7 — он ПОТРЕБИТЕЛЬ digest'а); журнал и события (P8.5); модель ошибок как таковая (P8.9 — здесь заводится один конкретный код в её форме); аудит решения по гейту (P8.7/P8.11); изоляция вызовов по метке происхождения — дело рантайма, а не контракта (§I2 прямо); правка золотого значения фазы P7 в любую сторону (расхождение — эскалация, не правка); ЛЮБЫЕ правки ревизии, схем, корпуса и PHP SDK.

**Implementation Rules:** состав входа digest'а и порядок полей берутся ДОСЛОВНО из правила ревизии — «логичный» порядок от себя ломает межъязыковой инвариант молча; канонизация вызывается только фасадом P8.3 (второй канонизатор запрещён); `descriptor_drift` — отдельный строковый код в модели §E1, слияние его с ошибкой авторизации либо валидации запрещено; золотое значение НЕ дублируется литералом без необходимости: сверка выполняется командой, извлекающей значение из закоммиченных данных PHP-теста (точный путь называет P7.4, исполнитель подставляет и печатает фактическую команду); если пара «вход → значение» физически не выражается в golden-механике фазы P6, дублирование литерала допускается КАК ИСКЛЮЧЕНИЕ, называется в Completion Notes вторым носителем и обновляет Q-16; `content_origin` не влияет на маршрутизацию внутри пакета — пакет только несёт метку (§I2); расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как P8.3, идиоматичный Dart, НЕ транслит PHP. Анти-самообман: «digest считается» ≠ «digest тот же, что в PHP» — доказательством считается ТРОЙКА: воспроизведённое побайтно золотое значение P7.4, изменение одного поля дескриптора меняет digest, commit со старым токеном даёт именно `descriptor_drift`. «Тест зелёный на своих данных» здесь не значит ничего: собственный вход + собственный выход доказывают лишь внутреннюю согласованность. Анти-подгонка: если digest не сходится с золотым — ЗАПРЕЩЕНО подкручивать сериализацию до совпадения: сначала разбирается СОСТАВ и ПОРЯДОК входа по правилу ревизии, затем канонизация P8.3 против векторов RFC 8785; если обе стороны формально правы — это недоспецифицированность, см. if-then. ЗАПРЕЩЕНО: заводить второй канонизатор; включать в digest поля, которых нет в правиле, «для надёжности»; сливать `descriptor_drift` с другими кодами; править золотое значение или тесты PHP; реализовывать изоляцию по `content_origin` внутри пакета. If-then: digest не совпал с золотым значением P7.4 → item НЕ закрывается «с отличиями»: (1) прогнать канонизацию P8.3 на официальных векторах RFC 8785 — красный там означает дефект P8.3, чинится там; (2) зелёный там и расхождение здесь означает расхождение СОСТАВА/ПОРЯДКА входа digest'а между реализациями → `🔴 Blocked` + эскалация с адресатом «владелец + фазы P3/P7», в отчёте приводятся оба входа побайтно и оба digest'а. Правка своей стороны «чтобы сошлось» без разбора — материальное отклонение. If-then: правило ревизии не задаёт порядок полей во входе digest'а однозначно → `🔴 Blocked` + эскалация (trigger «конфликт правил»): недоговорённость здесь = гарантированное расхождение языков, цена — новая датированная ревизия (D19/D62). If-then: золотое значение P7.4 в дереве отсутствует (фаза P7 его не зафиксировала) → `🔴 Blocked` + `Возобновление:` с адресатом «фаза P7, item P7.4»: якорь не изобретается заново этой фазой, иначе «байт-идентичность» станет утверждением о самом себе.
