### P8.5 — Журнал действия + контракты персистентности в Dart (§C1–§C3, §C5–§C7, D13)

**Intent:** Реализовать документ `03` (правила `ALC-*`): журнал как источник истины — append с `expected_prev_seq` и типизированной ошибкой конфликта, детерминированная свёртка состояния и полный набор состояний FSM, журналирование недетерминированного ввода как immutable payload, версионирование событий с апкастингом, снапшот отдельно от журнала, хеш-цепочка записей; плюс порты персистентности `EventLog`/`SessionStore`/`Clock` с in-memory реализациями (D13). Хеш-цепочка обязана совпасть с PHP побайтно на одном списке событий.
**Why:** «Журнал — истина, replay — проекция» (§C1) — выбор, сделанный именно потому, что строгий replay физически не переносится между языками: две реализации сойдутся только на чтении и свёртке журнала. Отсюда цена ошибки в Dart: недетерминированная свёртка или пропущенное журналирование недетерминированного ввода дают расхождение с PHP, которое проявится не тестом, а разными результатами на одном векторе. Отдельная ловушка языка: в Dart легко получить недетерминизм бесплатно — порядок обхода `Map` зависит от порядка вставки, а не от ключа, и свёртка, опирающаяся на него, будет зелёной локально и разойдётся с PHP на другом порядке событий. `expected_prev_seq` — единственное место, где спека нормирует гонку (§C3: ни Temporal, ни Restate, ни DBOS не дают этого готовым для доменного лога), а хеш-цепочка (§C7) — единственная часть аудита, требующая согласия МЕЖДУ реализациями. Порты персистентности — контракт, который в контуре Axioma будет реализован поверх реальной БД: спроектированный под массив в памяти, он не ляжет. `RAG:— (repo-grounded: DR-01 §C1–§C3, §C5–§C7 — модель детерминизма, immutable payload, optimistic concurrency, апкастинг, снапшот, хеш-цепочка «единственная часть, требующая согласия между реализациями»; §C8 — память агента вне спеки; plan.md §5 D13, D90; research/07-… §8, §9, §12)`.
**Scope Included:** (а) типы событий журнала и их сериализация по документу `03` и его схемам; (б) `append` с обязательным `expected_prev_seq` и ТИПИЗИРОВАННОЙ ошибкой конфликта версий (обязанность вызывающего — перечитать и повторить); (в) детерминированная свёртка журнала в состояние + полный набор состояний FSM и переходов ровно по таблице документа `03`; (г) журналирование недетерминированного ввода как immutable payload (§C2): результат LLM-вызова, метка времени, случайные значения, идемпотентные ключи попадают В ТЕЛО события и при восстановлении ЧИТАЮТСЯ, а не вычисляются заново; (д) `event_version` и цепочка апкастов по типу события; мутация записанных событий запрещена ТИПАМИ (`final` поля, неизменяемые коллекции), а не соглашением; (е) снапшот как отдельная сущность с собственным жизненным циклом (§C6); (ж) хеш-цепочка: каждая запись несёт `prev_hash`, формат канонизации — фасад P8.3; **побайтное совпадение цепочки с PHP** на одном списке событий (межъязыковой якорь, `research/07-…` §9); (з) порты `EventLog`, `SessionStore`, `Clock` в `lib/src/contracts/` — МИНИМАЛЬНАЯ поверхность, выведенная из семантики документа `03`, идиоматичная Dart (`Future`-возвращающие операции там, где реализация будет асинхронной), плюс in-memory реализации (D13); (и) детерминированные идентификаторы событий по правилу, ЗАПИСАННОМУ в ревизии; (к) тесты, чьи ожидания взяты из векторов `ALC-*`, с перечнем заимствованных `id`.

**Implementation Rules:** порт выводится из СЕМАНТИКИ документа `03` (optimistic concurrency, снапшот отдельно, неизменяемость записей), а не из удобства in-memory реализации и не из сигнатур PHP-порта: метод, осмысленный только для массива в памяти, запрещён; расширения «про запас» запрещены (`DR-01` §E6); свёртка ДЕТЕРМИНИРОВАНА: системные часы и случайность в ней не читаются (время — из порта `Clock`), а любой обход `Map` в логике свёртки и канонизации идёт по ОТСОРТИРОВАННЫМ ключам — порядок вставки не является порядком (это тихий источник расхождения с PHP); мутация записанного события запрещена типами (`final` поля, `List.unmodifiable`/`Map.unmodifiable`), а не комментарием; хеш-цепочка считается через фасад канонизации P8.3, второй канонизатор запрещён; побайтная сверка цепочки с PHP делается против золотых данных `php/tests/Journal/**` командой; форма идентификатора события берётся из документа `03`; расхождение с вектором разбирается прогоном против эталонного адаптера И адаптера PHP, все выводы — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Идиоматичный Dart, НЕ транслит PHP: свёртка — ЧИСТАЯ функция «список событий → состояние» (единственный способ доказать детерминизм таблицей кейсов); состояния FSM — `enum` либо `sealed class` по таблице документа `03`; события — `final class` с `final` полями и неизменяемыми коллекциями. Анти-самообман: «журнал реализован» ≠ «журнал защищает инварианты» — доказательством считаются ТРИ отрицательных прогона: append с неверным `expected_prev_seq` даёт типизированную ошибку конфликта, попытка мутации записанного события отвергается, свёртка одного и того же списка событий дважды даёт побайтно равный результат; «цепочка считается» ≠ «цепочка та же, что в PHP» — нужен побайтный якорь. Анти-подгонка: если вектор не сходится, разбирается таблица переходов документа `03`, а не «дополняется» состояние FSM; если цепочка не сходится с PHP — сначала проверяется P8.3 на векторах RFC 8785, затем состав входа хеша по §C7, и только потом эскалация. ЗАПРЕЩЕНО: читать системные часы в логике свёртки; вычислять недетерминированный ввод заново при восстановлении; полагаться на порядок вставки `Map`; заводить в порту метод без потребителя; мутировать записанные события; складывать снапшот в тот же поток, что журнал; транслитерировать `php/src/Journal/**`. If-then: документ `03` не задаёт форму детерминированного идентификатора события либо формат канонизации хеш-цепочки → `🔴 Blocked` + эскалация (trigger «конфликт правил») с ценой «новая датированная ревизия» (D19/D62): это ровно та часть, которая требует согласия МЕЖДУ реализациями (§C7). If-then: цепочка расходится с золотыми данными PHP при зелёном P8.3 → `🔴 Blocked` + эскалация с адресатом «владелец + фазы P3/P7», оба байтовых выхода и вход — в отчёте.
