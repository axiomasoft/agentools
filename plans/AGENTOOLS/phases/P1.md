# P1 — Conformance: adapter-протокол, runner, CI

## Phase Context

Строим исполняемый контроль договора: спека дополняется документом 07 (adapter-протокол),
пишется runner (PHP ≥8.3 CLI, без фреймворка — Decision D6 плана), который скармливает
векторы из `fixtures/vectors/` любому SDK через его CLI-адаптер (JSONL по stdio) и сверяет
факт с expect. Самотест — «null-адаптер» на PHP, эмулирующий эталонное поведение для
подмножества векторов. Финал — CI-workflow: spec_lint + runner self-test. Фаза закрыта,
когда runner детерминированно гоняет все L1/L2-векторы против null-адаптера с ожидаемыми
результатами (включая нарочно красный прогон) и это подключено в CI. Вход фазы — весь
выход P0 (спека + fixtures + spec_lint зелёный).

### P1.1 — 07_conformance-adapter.md: JSONL-протокол адаптера

**Status:** ⬜ Not started
**Intent:** Дописать в ревизию спеки документ 07: протокол «runner ↔ SDK-адаптер» (JSONL по stdio) + схему `schema/adapter-messages.json`.
**Why:** Оба SDK будут реализовывать этот CLI-контракт (P2.8, P3.8); без нормативного описания адаптеры разъедутся.
**Scope Included:** сообщения runner→adapter: `{"type":"init","spec_rev":"2026-07-draft","level":"L1"}`, `{"type":"run","vector":{…полный вектор…}}`, `{"type":"shutdown"}`; adapter→runner: `{"type":"ready","sdk":"php|dart","sdk_version":…,"levels":["L1","L2"]}`, `{"type":"event","event":{…конверт из 02…}}` (поток по мере исполнения), `{"type":"tool_call","tool":…,"phase":"prepare|commit","args":{…}}`, `{"type":"result","final_state":…,"error":?}`; правила: одна JSON-строка = одно сообщение, UTF-8, stdout только протокол (логи — stderr), тайм-аут вектора 30 с → fail; адаптер держит per-vector чистое состояние (in-memory реализации хранилищ); драйверинг script-шагов вектора (user_input/llm_stub/clarification_answer/approval/tick_seconds) — как runner передаёт их адаптеру: включены в `run.vector`, адаптер сам исполняет сценарий по script (время — виртуальное, tick_seconds сдвигает его «часы»).
**Scope Excluded:** реализация runner (P1.2); сетевые транспорты (stdio only v1).
**Inputs:** формат вектора из P0.9; конверт событий из 02.
**Files:** `spec/revisions/2026-07-draft/07_conformance-adapter.md`, `schema/adapter-messages.json`
**Required Reads:** 1) fixtures/README.md 2) spec/revisions/2026-07-draft/02_action-lifecycle.md 3) plans/AGENTOOLS/plan.md §5 (D6, D8) 4) plans/AGENTOOLS/20_research/R-06_cross-language.md (Findings: MCP conformance — образец).
**Implementation Rules:** правила `CA-*`; примеры полного диалога (init→ready→run→events→result) для happy-path вектора №2 из P0.9; виртуальное время описать явно (адаптер НЕ спит на tick_seconds).
**Code Guidance:** Кода нет. adapter-messages.json — oneOf по type, стиль как прочие схемы.
**Validation:** `python3 tools/spec_lint.py spec/revisions/2026-07-draft` зелёный (док 07 добавить в список обязательных).
**Deliverables:** 07_conformance-adapter.md + adapter-messages.json + пример диалога.

### P1.2 — Runner (PHP CLI) + формат отчёта

**Status:** ⬜ Not started
**Intent:** Реализовать `conformance/bin/run` (PHP ≥8.3, plain, composer только для автозагрузки/dev-тестов): грузит векторы, запускает адаптер как subprocess, ведёт JSONL-диалог, матчит expect, пишет отчёт JSON + человекочитаемый итог, exit-код по результату.
**Why:** Runner — механический судья договора; от его корректности зависит смысл «зелёного SDK».
**Scope Included:** CLI: `run --adapter "<cmd>" --vectors fixtures/vectors [--level L1] [--filter id-prefix] --report out/report.json`; матчер expect (алгоритм частичного матча из fixtures/README дословно); отчёт: {spec_rev, adapter.ready-данные, totals {pass,fail,skip}, per-vector {id, pass, mismatches[]}}; mismatches — человекочитаемые («ожидалось событие approval_requested после seq 3 — не найдено»); тайм-аут и краш адаптера = fail вектора, не runner'а; unit-тесты матчера (Pest или phpunit — что выберет исполнитель, зафиксировать в Completion Notes) на таблице кейсов: подмножество/порядок/"!field"/отсутствие.
**Scope Excluded:** параллельный запуск векторов (последовательно в v1); Dart-специфика.
**Inputs:** 07 (P1.1), fixtures (P0.9).
**Files:** `conformance/bin/run`, `conformance/src/**` (Loader, AdapterProcess, Matcher, Report), `conformance/composer.json`, `conformance/tests/**`
**Required Reads:** 1) spec/revisions/2026-07-draft/07_conformance-adapter.md 2) fixtures/README.md (алгоритм матча) 3) fixtures/schema/fixture.json.
**Implementation Rules:** PHP ≥8.3, strict_types, без фреймворков/симфони-компонентов (proc_open + потоки руками); зависимость допустима одна — JSON Schema валидатор из пинов R-08 (валидация векторов на входе); сообщения на русском.
**Code Guidance:** Matcher — чистые функции над массивами (тестируемость); AdapterProcess — единственное место proc_open, неблокирующее чтение stdout/stderr с тайм-аутом; никаких shell-строк с интерполяцией аргументов (массив-форма proc_open). Запрещено: глотать stderr адаптера (включать в mismatches при fail), «умные» авто-починки векторов.
**Validation:** `cd conformance && composer install && vendor/bin/pest` (или phpunit) зелёный; `bin/run --adapter 'php tests/fixtures/broken-adapter.php' …` корректно падает с внятным отчётом.
**Deliverables:** рабочий runner + тесты матчера + формат отчёта.

### P1.3 — Null-адаптер + самотест runner'а + L3-векторы

**Status:** ⬜ Not started
**Intent:** Написать эталонный null-адаптер (PHP, in-memory, реализует ровно семантику спеки для L1-подмножества) + самотест «runner × null-адаптер»; дописать отложенные L3-векторы (url-elicitation, double_confirm, исполнение компенсации).
**Why:** Без эталона нельзя отличить баг runner'а от бага SDK; L3-векторы были Pending Work P0.9.
**Scope Included:** null-адаптер `conformance/adapters/null/adapter.php`: интерпретирует script вектора, честно ведёт FSM/события/токены/idempotency в памяти по правилам спеки (это микро-референс семантики, НЕ полноценный SDK — без LLM, без MCP, только протокольная логика); самотест: прогон всех L1/L2-векторов → все pass; прогон с нарочно испорченным вектором-мутантом (ожидание неверного события) → fail (доказывает, что runner ловит расхождения); +3–5 L3-векторов и их поддержка в null-адаптере.
**Scope Excluded:** производительность; параллелизм.
**Inputs:** runner (P1.2), спека 01–07, fixtures.
**Files:** `conformance/adapters/null/**`, `fixtures/vectors/l3/*.json`, `conformance/tests/SelfTest*`
**Required Reads:** 1) spec/revisions/2026-07-draft/{02,03,06}_*.md (семантика для реализации) 2) 07_conformance-adapter.md 3) fixtures/README.md.
**Implementation Rules:** null-адаптер ≤ ~600 строк, один файл допустим; та же дисциплина PHP что в P1.2; каждое отклонение null-адаптера от спеки = дефект спеки или адаптера → разобраться, не подгонять вектор.
**Code Guidance:** Виртуальные часы (tick_seconds) — поле объекта, не time(); ULID событий — детерминированный счётчик-заглушка (`00000000000000000000000001`-стиль), спека этого не запрещает для тестовых реализаций — если запрещает (проверить 02), добавить в 02 явное разрешение для conformance-режима через мини-правку с пометкой в Completion Notes.
**Validation:** `bin/run --adapter 'php conformance/adapters/null/adapter.php' --vectors fixtures/vectors --report out/self.json` → totals.fail == 0; прогон вектора-мутанта → fail == 1; отчёт самотеста приложить в Completion Notes.
**Deliverables:** null-адаптер + зелёный самотест + красный мутант-тест + L3-векторы.
