### P3.20 — Непересекающиеся open-enum схемы clarification/tasks

**Intent:** Исправить `ResultType`, `StatusChannel` и `TaskStatus`, чтобы каждое core-значение удовлетворяло ровно одной ветви `oneOf`, vendor-значение — только fallback, и закрепить этот контракт адресным stdlib-selftest.
**Why:** Сейчас три опубликованные и три производные authoring-схемы отвергают собственные core-значения из-за пересечения `const` и свободной string-ветви; это ломает примеры документов `05`/`07` и будущие fixtures/SDK при формально зелёном A2. `RAG:— (repo-grounded: Audit P3 F1/F3; schema/clarification.json:65; schema/task-binding.json:33,51)`.
**Scope Included:** в published-схемах fallback каждого из трёх `$defs` сохраняет `type: string`/`minLength: 1`, но исключает exact core-набор через `not` + `enum`; authoring-схемы только регенерируются; `tools/spec_lint.py` получает общий `check_open_enum_contracts` и CLI `--schema-values-selftest <revision_dir>`, который для каждого extensible string `$defs` сверяет core-набор, исключение fallback и positive/negative probes (`core`, `vendor`, пустая строка).
**Scope Excluded:** изменение core-значений; переход на `anyOf`/закрытый `enum`; `EventKind` (P3.21); нормативный текст `05`/`07`/`09`; fixtures P4; универсальный JSON Schema validator или новая зависимость.
