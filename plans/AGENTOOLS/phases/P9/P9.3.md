### P9.3 — Адаптеры поведения: `LlmPort` поверх AiGateway, `ToolPort` поверх ToolRegistry, доставка протокольных объектов

**Intent:** Реализовать в доме среза три адаптера поведения по утверждённому INT-001: `LlmPort` — ТОЛЬКО через фасад AiGateway с неприкосновенным порядком middleware (`ADR-020`), `ToolPort` — поверх единственного `ToolRegistry` контура (`ADR-022` п.1) с двухуровневым permission-гейтом, доставку протокольных объектов (уточнение, превью, отложенное подтверждение) в продуктовый канал контура.
**Why:** Здесь ломается то, что снаружи выглядит работающим. Порядок middleware AiGateway (`маска ПДн → budget-check → драйвер → usage-ledger → трейс`) не переставляется не из вкуса: обход маски отправляет ПДн в лог провайдера, а обход бюджета даёт агенту петлю retry-шторма — и оба дефекта видны только постфактум, по счетам и по логам. Permission-гейт обязан работать на ДВУХ уровнях (недоступный инструмент не существует в каталоге И отвергается при прямом вызове, `ADR-022` п.5 / `B-32` §3.6): реализованный на одном, он выглядит рабочим на UI-пути и пропускает вызов от внешнего клиента. Отдельно про уточнения: MRTR (§B1) — единственный биндинг на MCP-ГРАНИЦЕ, а продуктовый UI не является MCP-клиентом; смешение биндинга с доставкой порождает ложный вывод «спека запрещает Reverb» и толкает исполнителя выбирать между несуществующими вариантами. `RAG:— (repo-grounded: ADR-020 — фиксированный порядок middleware, запрет прямого вызова драйвера, LLM_QUOTA_EXCEEDED; ADR-022 п.1, п.4, п.5; B-32 §3.6; DR-01 §B1 — MRTR как биндинг уточнений; research/08-p9-crm-slice-2026-08.md §7, §9; plan.md §5 D12)`.
**Scope Included:** (а) адаптер `LlmPort` → фасад AiGateway: ни одного прямого обращения к `ChatDriver`/`SttDriver`/`EmbeddingDriver`, отсутствие обхода доказывается грепом; ошибка бюджета приходит структурным кодом (`LLM_QUOTA_EXCEEDED`) и отображается на модель ошибок SDK как **tool execution error**, а не как протокольная; (б) адаптер `ToolPort` → `ToolRegistry` контура: дескрипторы берутся из реестра, второй реестр не заводится (`ADR-022` п.1); двухуровневый permission-гейт — фильтрация каталога по субъекту И повторная проверка при исполнении; субъект выбирается по правилу `B-32` §3.6 (живой инициатор → имперсонация-пересечение; автономный запуск → сервисный `run_as`), «система без субъекта» не допускается; (в) доставка протокольных объектов в продуктовый канал контура по INT-001 (в контуре Flex — приватный канал вещания, тенантно-ограниченный): доставляются объекты протокола КАК ЕСТЬ, адаптер их не интерпретирует и не переименовывает поля; (г) отображение классификации побочного эффекта по таблице INT-001 — единственной, без локального словаря; (д) `Clock`-адаптер контура (подменяемый — иначе E2E невоспроизводим); (е) feature-тесты трёх адаптеров, включая ЧЕТЫРЕ отрицательных: прямой вызов драйвера в обход AiGateway не проходит, превышение бюджета даёт названный код, инструмент вне прав НЕ ВИДЕН в каталоге, он же отвергается при прямом вызове.
**Scope Excluded:** персистентные сторы `EventLog`/`SessionStore`/`IdempotencyStore`/`TokenSigner`/`AuditSink` и миграции (P9.4); доменные инструменты и сценарий (P9.5); UI-потребление доставленных объектов (P9.6); правки самого AiGateway, `ToolRegistry` и любого кода канонных пакетов сверх утверждённых INT-001 предложений; реализация RAG/эмбеддингов и векторного поиска (вне среза); правки ревизии, корпуса, SDK и канона Flex.

**Implementation Rules:** машинно-специфичный корень репозитория пакета (D36) — `~/projects/packages/agentools`; команды `Validation` над ним запускаются из этого корня и записаны репо-относительно; адаптеры ТОНКИЕ — ни одной строки бизнес-семантики SDK не дублируется; логика, появившаяся в адаптере и отсутствующая в `php/src/**`, означает дефект SDK и чинится эскалацией с адресатом-item'ом фазы P7, а не в мосте; порядок middleware AiGateway не переставляется и не обходится ни при каких условиях, включая отладку — временный обход в коммите есть материальное отклонение; permission-гейт реализуется НА ДВУХ уровнях, оба проверяются отдельными тестами; субъект вызова определяется правилом `B-32` §3.6, «система без субъекта» запрещена кодом, а не соглашением; объекты протокола доставляются без переименования полей — переименование делает UI зависимым от адаптера и ломает контракт; отображение классификации эффекта берётся ТОЛЬКО из таблицы INT-001; канал доставки тенантно-ограничен, проверка изоляции — тест, а не комментарий; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — конвенции дома среза (пакет CoreX либо приложение), комментарии по `general:writing-style` — объяснять «почему». Анти-самообман: «адаптер работает» ≠ «обход невозможен» — доказательством считаются ЧЕТЫРЕ отрицательных прогона (прямой вызов драйвера, превышение бюджета, невидимость инструмента в каталоге, отказ при прямом вызове); «канал приватный» без теста кросс-тенантной изоляции не сдан. Анти-подгонка: если сигнатура порта неудобна для контура — правится АДАПТЕР, а не порт; неудобство, которое нельзя обойти адаптером, есть дефект порта и адресуется фазе P7 эскалацией, а не локальной правкой SDK. ЗАПРЕЩЕНО: звать драйвер в обход AiGateway; заводить второй реестр инструментов; интерпретировать объекты протокола в адаптере; хардкодить идентификатор модели; ослаблять `side_effect` настройкой; тянуть в дом среза зависимость на Dart-контур; править `php/src/**`. If-then: фасад AiGateway на дату исполнения не существует (пакет создан, гейтвей — нет) → `🔴 Blocked` + `Возобновление:` с адресатом «владелец + `FLEX-2` P6.15»: писать собственный гейтвей ЗАПРЕЩЕНО (это второй носитель факта о бюджете и ПДн). If-then: `ToolRegistry` не даёт способа отфильтровать каталог по субъекту → `🔴 Blocked` + эскалация: односторонний permission-гейт не принимается, а расширение чужого реестра — предложение через INT-001, не правка по месту.
