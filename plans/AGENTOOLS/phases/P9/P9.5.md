### P9.5 — Доменные инструменты + сценарий среза + продуктовые векторы

**Intent:** Реализовать MVP-набор доменных инструментов среза по профилю ревизии (классификация побочного эффекта из таблицы INT-001, two-phase для мутационных, пиннинг дескриптора), сценарий сквозного среза «итог дня → черновик → уточнения → превью → запись» и продуктовые векторы к нему — на ЗАСКРИПТОВАННОМ LLM (D8), плюс доказать, что запрос подтверждения РОВНО ОДИН.
**Why:** Инструменты — место, где протокол встречается с доменом, и где легче всего получить ложно-зелёное: набор, состоящий из одних `read`-инструментов, проходит весь сценарий, ничего не подтверждая, и «срез работает» становится правдой без единой проверки гейта. Отдельно — единственность гейта: разведение трёх механизмов подтверждения (INT-001) проверяется не чтением контракта, а прогоном, в котором продуктовый путь включён целиком; нативный HITL, который «отключён», но просто не срабатывал на тестовом наборе, — самый вероятный способ сдать фазу с двумя подтверждениями. И третье: пиннинг дескриптора (§B7) в продукте проверяется иначе, чем в SDK, — здесь дескриптор приходит из ЖИВОГО реестра инструментов контура, и его дрейф между prepare и commit физически возможен (модуль включили/выключили, права поменяли). `RAG:— (repo-grounded: DR-01 §B2, §B3, §B5, §B7, §I4 — токен, edit как новый цикл, dual control, пиннинг дескриптора, событие решения; §F4 — saga и COMPENSATION_FAILED; plan.md §5 D8 — в fixtures LLM только заскриптован, D10, D11 — грамматика выражений и маршруты отказа шага; ADR-022 п.4, п.6; research/08-p9-crm-slice-2026-08.md §5, §9)`.
**Scope Included:** (а) MVP-набор доменных инструментов среза: не менее одного `read`, одного `draft` и одного `write` — набор БЕЗ мутационного инструмента не принимается; каждый несёт классификацию побочного эффекта из таблицы INT-001 и объявленную идемпотентность для мутационных (`ADR-022` lint-правило (б)); (б) сценарий среза по документу `06` ревизии: шаги, уточнения через единственный биндинг MRTR, превью, подтверждение, запись; маршруты отказа шага — по D11; (в) two-phase для мутационных инструментов через Protocol Layer SDK: prepare → превью → commit с подписанным токеном, TTL, `edit` как НОВЫЙ цикл prepare (§B3), обязательное событие решения §I4; (г) пиннинг дескриптора в живом контуре: изменение дескриптора между prepare и commit даёт `descriptor_drift`, а не generic ошибку; (д) **продуктовые векторы** в формате корпуса (`fixtures/2026-08/README.md`), ссылающиеся на правила ревизии, — живут в репозитории `agentools` под собственным каталогом продуктового набора, ЗАМОРОЖЕННЫЙ корпус `fixtures/2026-08/**` не правится НИ НА БАЙТ; LLM в векторах только заскриптован (D8); (е) прогон продуктовых векторов раннером фазы P6 — ноль отказов вне baseline; (ж) **доказательство единственности гейта**: прогон полного продуктового пути показывает РОВНО ОДИН запрос подтверждения (счётчик приводится выводом).
**Scope Excluded:** UI-потребление (P9.6); E2E с реальной моделью (P9.7 — здесь только заскриптованный); адаптеры и сторы (P9.3, P9.4); нормирование агентной поверхности модулей (чужой норматив `ADR-022`/`B-32`); расширение набора инструментов сверх нужд среза (`DR-01` §E6); правки замороженного корпуса `fixtures/2026-08/**`, ревизии, схем и SDK; RAG/векторный поиск и голосовой ввод (голос — P9.6).
**Inputs:** адаптеры поведения (P9.3) · сторы персистентности (P9.4) · утверждённый INT-001 (P9.2) — таблица классификации эффекта и единственное имя инструмента в покрытии токена · `spec/revisions/2026-08/02_tool-contract-profile.md`, `04_confirmation.md`, `05_clarification-mrtr.md`, `06_*.md` · `fixtures/2026-08/README.md` (формат вектора, алгоритм матча, семантика `!field`) · `conformance/bin/run` · `phases/P7.md` items P7.4, P7.7, P7.10 · `10_decisions/DR-01_architecture-2026-08.md` §B2–§B7, §F4, §I4 · `plan.md` §5 (D8, D10, D11) · `research/08-p9-crm-slice-2026-08.md` §5, §9.
**Files:** `<ДОМ-СРЕЗА>` (вердикт P9.1): доменные инструменты `**/AgenTools/Tools/Domain/**`, сценарий среза, их тесты · `~/projects/packages/agentools`: каталог продуктовых векторов среза (имя — по INT-001, вне `fixtures/2026-08/**`) · точные пути приводятся в Completion Notes

**Implementation Rules:** машинно-специфичный корень репозитория пакета (D36) — `~/projects/packages/agentools`; команды `Validation` над ним запускаются из этого корня и записаны репо-относительно; набор инструментов минимален и покрывает сценарий среза — «про запас» не заводится ничего (`DR-01` §E6); классификация побочного эффекта берётся ТОЛЬКО из таблицы INT-001, локальный словарь запрещён; two-phase исполняется Protocol Layer'ом SDK, а не собственной механикой в инструменте — собственный гейт в доменном коде есть второй носитель решения; продуктовые векторы пишутся в формате замороженного корпуса и ссылаются на идентификаторы правил ревизии, но живут ОТДЕЛЬНО от него — `fixtures/2026-08/**` не правится ни на байт; LLM в векторах только заскриптован (D8), сетевых вызовов в векторах нет; счётчик запросов подтверждения снимается прогоном, а не рассуждением; расхождение продуктового вектора с реализацией разбирается сначала прогоном того же класса случая против эталонного адаптера либо in-memory SDK, оба вывода — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — конвенции дома среза; инструменты тонкие и детерминированные, вся недетерминированность (ответ модели, время, случайность) приходит В ТЕЛЕ события журнала (§C2), а не вычисляется в инструменте. Анти-самообман: «сценарий проходит» ≠ «гейт работает» — доказательством считаются ТРИ отрицательных прогона: commit с подменённым после превью аргументом отвергается, просроченный токен приходит как tool execution error, повторный commit тем же токеном отвергается; плюс ЧЕТВЁРТЫЙ — счётчик запросов подтверждения на полном продуктовом пути равен ОДНОМУ. «Инструменты реализованы» без мутационного инструмента в наборе не сдано. Анти-подгонка: если сценарий не сходится с правилом ревизии — разбирается ПРАВИЛО, а не «упрощается» сценарий; если продуктовый вектор красный — чинится реализация, а не вектор. ЗАПРЕЩЕНО: писать собственный гейт подтверждения в доменном коде; править замороженный корпус, ревизию и SDK; вызывать реальный LLM или сеть в векторах; заводить инструменты без потребителя в сценарии; ослаблять классификацию эффекта; добирать зелёный прогон флагом фильтрации или baseline. If-then: сценарий среза требует правила, которого нет в документах `05`/`06` ревизии → `🔴 Blocked` + эскалация (trigger «конфликт правил») с ценой «новая датированная ревизия» (D19/D62), решение владельца. If-then: счётчик запросов подтверждения больше одного → item НЕ закрывается «с оговоркой»: `🔴 Blocked` + `Возобновление:` с адресатом «item P9.2» (развод гейтов не сработал — чинится КОНТРАКТ и его реализация, а не отключается тест).
**Validation:** тесты дома среза зелёные, статический анализ зелёный (команды — в Completion Notes; коды возврата 0) · прогон продуктовых векторов раннером фазы P6 — код возврата 0, ноль отказов вне baseline (команда и вывод — в Completion Notes) · набор инструментов содержит не менее одного `read`, одного `draft` и одного `write` — перечень с классификацией приведён в Completion Notes · отрицательный прогон: commit с подменённым после превью аргументом отвергается (вывод — в Completion Notes) · отрицательный прогон: просроченный токен приходит как tool execution error (вывод — в Completion Notes) · отрицательный прогон: повторный commit тем же токеном отвергается (вывод — в Completion Notes) · отрицательный прогон: изменение дескриптора между prepare и commit даёт `descriptor_drift`, а не generic ошибку (вывод — в Completion Notes) · **счётчик запросов подтверждения на полном продуктовом пути равен 1** (команда и вывод — в Completion Notes) · тест уточнений: многораундовое уточнение проходит единственным биндингом MRTR — зелёный · `git status --short -- fixtures/2026-08 spec php conformance/bin conformance/adapters | wc -l` = 0 из корня репозитория пакета (замороженный корпус, ревизия, SDK и механики фазы P6 не тронуты) · прогнать плановый линтер по каталогу плана и опубликовать счёт с атрибуцией, K = 0.
**Deliverables:** MVP-набор доменных инструментов с классификацией из INT-001 и объявленной идемпотентностью мутационных + сценарий среза на единственном биндинге уточнений + продуктовые векторы вне замороженного корпуса, зелёные через раннер фазы P6 + четыре отрицательных прогона гейта с выводом + доказанный счётчиком ЕДИНСТВЕННЫЙ запрос подтверждения.
