### P0.3 — 01_tool-contract-profile.md + схемы

**Intent:** Написать нормативный документ «Tool Contract Profile»: какие требования AgenTools накладывает на MCP-tool (2025-11-25) и какие расширения несёт в `_meta`, включая two-phase конвенцию write-tools; + схемы `schema/tool-descriptor.json`, `schema/side-effect.json`.
**Why:** Это фундамент спеки: контракт tool — то, что оба SDK и оба контура (corex ToolRegistry, axioma_mcp AxiomaTool) обязаны уметь выразить.
**Scope Included:** Документ с разделами: (1) базис = MCP 2025-11-25 tools (name/title/description/inputSchema/outputSchema/annotations) — что MUST/SHOULD; (2) правила имени `{module}_{resource}_{verb}` (snake, ≤64); (3) аннотации: все четыре (readOnlyHint/destructiveHint/idempotentHint/openWorldHint) MUST задаваться явно; для внутренних (trusted) серверов аннотации = enforcement-сигнал; (4) расширение `_meta["agentools/v1"]` объекта tool: `side_effect: read|draft|write|irreversible`, `confirmation: none|confirm|double_confirm` (дефолт выводится из side_effect по таблице D7 мастер-плана), `idempotent_commit: bool`, `permissions_hint: string[]`; (5) two-phase конвенция D4: вызов write/irreversible-tool без `confirmation_token` → prepare, MUST вернуть preview в `structuredContent` + блок `_meta["agentools/v1"] = {confirmation_token, expires_at, preview_digest}`; вызов с `confirmation_token` (зарезервированное имя аргумента) → commit; (6) правила ответов read-tools: `response_format: concise|detailed`, пагинация `next_cursor`, human-readable ids (канон B-13 flex); (7) видимость: tool, недоступный по правам, MUST отсутствовать в tools/list (двойная проверка при вызове); (8) совместимость: чем профиль отличается от «голого» MCP и как деградирует для внешних MCP-клиентов без поддержки `_meta`. Схемы: tool-descriptor.json (профиль-надстройка: имя, аннотации, `_meta`-блок), side-effect.json (enum'ы + таблица соответствия side_effect→confirmation по умолчанию). ≥2 полных json-примера (read-tool и write-tool с prepare/commit).
