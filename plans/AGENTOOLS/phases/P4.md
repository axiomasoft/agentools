# P4 — MVP FlexCRM: сценарий «отчёт о проделанной работе» E2E

## Phase Context

Первая продуктовая интеграция: вертикальный срез в контуре Flex — сотрудник пишет/наговаривает
итог дня, агент формирует деловой черновик отчёта, задаёт уточнения, показывает preview,
после подтверждения пишет в БД. Работа идёт в ДВУХ репозиториях: пакет `agentools` (донастройки)
и код Flex (corex/ai + flexcrm) — по `architect:package-contribution-protocol` (SDK — depended-on
пакет: вклад через минимальный контракт, направление зависимости corex/ai → agentools/sdk).
ВАЖНО: статус кodovой базы Flex определяет 50_execution roadmap flex-программы — item P4.1
начинается со сверки, что там уже реализовано (corex/ai может быть ещё не начат — тогда его
минимальный каркас входит в P4 по решению item'а P4.1). UI-канал — Reverb (private-каналы),
голос в MVP — batch-STT (файл → текст), streaming — вне scope. Фаза закрыта, когда сценарий
`crm.daily_report@1` проходит E2E на dev-стенде FlexCRM с реальным LLM (YandexGPT/GigaChat
через AiGateway) и все продуктовые векторы P4.3 зелёные через conformance.

### P4.2 — Реализация портов: AiGateway-LLM, ToolRegistry, Reverb-clarification, тенантские сторы

**Status:** ⬜ Not started
**Intent:** Реализовать в corex/ai адаптеры портов agentools/sdk по контракту INT-001: LlmPort поверх AiGateway (маска ПДн → бюджет → драйвер → ledger — порядок ADR-020 неприкосновенен), ToolPort поверх ToolRegistry (права AzGuard: intersection(user, agent-role), недоступный tool невидим), ClarificationTransport поверх Reverb-событий, EventLog/SessionStore/PendingActionStore/IdempotencyStore поверх тенантских таблиц (миграции).
**Why:** Это и есть «corex/ai реализует AgenTools» (D8 мастер-плана) в коде.
**Scope Included:** адаптеры + миграции ai_*-таблиц по DDL-скетчу INT-001; feature-тесты адаптеров (testbench, Postgres); деградация ai.enabled=false (нет ключей LLM) не ломает CRM (канон ADR-020).
**Scope Excluded:** UI (P4.4); сами tools (P4.3); голос-streaming.
**Inputs:** INT-001; SDK P2; corex-конвенции модулей (B-10).
**Files:** в репо corex: `packages/ai/src/AgenTools/**` (адаптеры), `packages/ai/database/migrations/**`, тесты — фактические пути уточняет INT-001.
**Required Reads:** 1) INT-001 2) php/src/Contracts/** (порты) 3) CoreX ADR-020 (vault: 05-Projects/03-Packages/CoreX/docs/03_Dev/ADR/ADR-020 AiGateway.md) 4) plans/flex/30_blueprints/B-11 (AzGuard-модель) — секции по ссылкам INT-001.
**Implementation Rules:** corex-конвенции (contract-first, префиксы таблиц, Extend-классы — по B-10); adapters тонкие: НИКАКОЙ бизнес-логики SDK не дублировать; событ題 write-tool → также запись в общий Audit Log corex (ACTOR-конвенция source: agent).
**Code Guidance:** LlmPort-адаптер не зовёт драйверы напрямую — только AiGateway-фасад; idempotency-стор — UNIQUE-индекс по key + upsert-семантика claim (SELECT ... FOR UPDATE или ON CONFLICT — по конвенциям corex, Postgres-first D4 flex); Reverb-канал — private, по конвенции B-16 (префикс-bootstrapper).
**Validation:** feature-тесты адаптеров зелёные на testbench+Postgres; conformance-прогон с адаптером «php-sdk с corex-сторами» (in-memory заменены на БД) по L1-векторам — fail=0 (это подтверждает эквивалентность сторов).
**Deliverables:** адаптеры + миграции + тесты + L1-прогон на БД-сторах.

### P4.4 — UI-конвейер: строка команды, preview-карточка, уточнения, подтверждение

**Status:** ⬜ Not started
**Intent:** Реализовать во FlexCRM UI-цикл: командная строка на главном экране (текст + загрузка аудио с batch-STT) → стрим статусов по Reverb → карточки уточнений (варианты/confirm) → preview-карточка (diff/сводка) с кнопками «Подтвердить/Отклонить/Правка» → результат; всё поверх событий/объектов SDK (никакой логики принятия решений в UI).
**Why:** Продуктовый смысл AI-first CRM — этот экран; UI лишь рендерит протокольные объекты (ClarificationRequest/preview/PendingAction), что доказывает достаточность протокола.
**Scope Included:** Inertia-страница/компоненты; Reverb-подписка (private-канал пользователя); отправка ответов (clarification answer, approval decision) через HTTP-эндпоинты corex/ai; batch-STT через SttDriver AiGateway (файл → текст, дальше единый текстовый вход); состояния UI = FSM-статусы сессии.
**Scope Excluded:** streaming-голос/realtime (Loqum, позже); мобильный UI; редактор сценариев.
**Inputs:** P4.2 (транспорт), P4.3 (сценарий); стек flex D4 (Inertia 3; JS-фреймворк за Inertia — уточнить по актуальному канону flex в момент исполнения, INT-001 фиксирует).
**Files:** flexcrm-репо (страница, компоненты, роуты, тесты) — пути по INT-001.
**Required Reads:** 1) INT-001 2) spec 03 (объекты clarification/preview — рендерим их 1:1) 3) plans/flex/30_blueprints/B-16 (Reverb-конвенции) 4) фактический UI-каркас flexcrm.
**Implementation Rules:** UI не интерпретирует side_effect/политики — только отображает то, что прислал бекенд (единственный источник истины — события SDK); тексты русские; доступность кнопок подтверждения ↔ статус PendingAction.

**Validation:** feature/browser-тест happy-path (текстовый ввод → уточнение → preview → confirm → запись видна в CRM); ручная демонстрация на dev-стенде.
