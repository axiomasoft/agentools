### P7.11 — Длинные операции, аудит и наблюдаемость, безопасность (документы `07`, `08`, `10`)

**Intent:** Реализовать три оставшихся документа ревизии: `07` (`LOP-*`) — длинные операции ОБОИМИ путями (поверх задачи MCP и синхронным вызовом без задач), немедленное журналирование идентификатора задачи, состояние «требует сверки», кооперативная отмена; `08` (`AOB-*`) — собственная схема аудита, поле корреляции, собственный подсчёт стоимости, непрозрачные идентификаторы baggage; `10` (`SEC-*`) — запрет проброса чужих токенов и различимая тройка принципалов в аудите.
**Why:** Каждый из трёх документов несёт правило, которое ломается тихо. §G1: расширение задач MCP — факультативная возможность контрагента, поэтому синхронный путь ОБЯЗАТЕЛЕН, и реализация «только через задачи» откажет ровно у офлайн-первого контура ERP, где расширения нет. §G3: идентификатор задачи журналируется НЕМЕДЛЕННО, иначе падение между запуском и записью оставляет висящую задачу без владельца. §H2: долгий гейт не держит span — трассировка, которая ждёт человека, ломает бюджеты наблюдаемости. §I1: посредник, принимающий чужие токены, — классический confused deputy, и оба SDK архитектурно посредники. §I3: тройка принципалов различима без фиксации claim-схемы, потому что RFC 8693 и драфты делегирования для агентов ещё не ратифицированы — зафиксировать схему сейчас значит переписывать её позже. `RAG:— (repo-grounded: DR-01 §G1 — оба пути обязательны в conformance; §G2 — прогресс в процентах не обещать; §G3 — идентификатор задачи журналируется немедленно; §G4 — состояние «требует сверки»; §G5 — отмена кооперативная; §H1–§H5 — своя схема аудита, долгий гейт не держит span, поле корреляции, стоимость считаем сами, baggage непрозрачен; §I1 — запрет проброса токенов; §I3 — тройка принципалов без фиксации claim-схемы; research/06-… §4 п.2, §8)`.
**Scope Included:** (а) длинные операции ОБОИМИ путями (§G1): поверх расширения задач и синхронным вызовом без задач вовсе — оба пути реализованы и оба покрыты тестами; (б) немедленное журналирование идентификатора задачи (§G3), состояние «требует сверки» (§G4), кооперативная отмена (§G5) — отмена запрашивается, а не навязывается; (в) отсутствие обещания прогресса в процентах (§G2): поля процента в контракте нет — доказывается грепом; (г) собственная схема аудит-события (§H1) плюс ОПЦИОНАЛЬНЫЙ порт экспорта `AuditSink` — экспорт не обязателен и не тянет зависимость; (д) правило §H2: долгий гейт подтверждения не держит span наблюдаемости; (е) поле корреляции как ПОЛЕ, а не зависимость от трассировщика (§H3); собственный подсчёт стоимости (§H4); baggage — только непрозрачные идентификаторы (§H5); (ж) §I1: токен, выпущенный не для нас, не принимается — отдельный отказ с названной диагностикой; (з) §I3: каждая запись о действии агента несёт различимую тройку (конечный пользователь, агент как принципал, область действия на конкретный вызов) БЕЗ фиксации механизма токенов делегирования; (и) тесты, чьи ожидания взяты из векторов `LOP-*`/`AOB-*`/`SEC-*`, с перечнем заимствованных `id`.
**Scope Excluded:** событие решения по гейту §I4 (P7.7 — уже реализовано, здесь только не ломается); метка происхождения аргумента §I2 (P7.4); реальный экспорт в OTel/иную систему — только порт (§H1: адаптер экспорта опционален); прогноз зрелости расширения задач MCP (Q-7: conformance от неё не зависит по построению, остаточный внешний факт адресован фазе P8); реализация изоляции карантинного маршрута — дело рантайма (§I2); retention и хранилище аудита (§C7 — не нормируются); ЛЮБЫЕ правки ревизии, схем и корпуса.

**Implementation Rules:** ОБА пути длинной операции обязательны и оба тестируются — реализация «только через задачи» не сдана (§G1); идентификатор задачи пишется в журнал ДО первого ожидания, порядок проверяется тестом; отмена кооперативная — принудительного прерывания в коде нет; поля прогресса в процентах в контракте нет (§G2) — отсутствие доказывается грепом, а не заявлением; порт `AuditSink` ОПЦИОНАЛЕН: отсутствие реализации не ломает работу пакета и не тянет зависимость; поле корреляции — обычное поле, зависимости от трассировщика в пакете нет (§H3); baggage несёт только непрозрачные идентификаторы, класть в него содержательные данные запрещено (§H5); чужой токен не принимается ни при каких условиях (§I1) — отдельный код отказа; тройка принципалов различима, но claim-схема НЕ фиксируется (§I3) — введение конкретной схемы делегирования запрещено, у неё нет ратифицированного стандарта; расхождение с вектором разбирается прогоном против эталонного адаптера, оба вывода — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как P7.5. Анти-самообман: «длинные операции реализованы» ≠ «оба пути работают» — доказательством считается ПАРА прогонов: один и тот же сценарий поверх задачи и без задач вовсе, оба зелёные; «аудит есть» ≠ «аудит доказуем» — нужен тест, показывающий различимую тройку принципалов в записи. Анти-подгонка: если синхронный путь не сходится с вектором, чинится путь, а не объявляется «задачи обязательны» — это прямо запрещено §G1 и обесценило бы офлайн-контур. ЗАПРЕЩЕНО: делать расширение задач жёсткой зависимостью; обещать прогресс в процентах; принудительно прерывать операцию; принимать чужой токен; фиксировать claim-схему делегирования; тянуть зависимость трассировки; класть содержательные данные в baggage. If-then: документ `07` не описывает поведение при недоступности расширения задач ПОСЕРЕДИНЕ операции → `🔴 Blocked` + эскалация (trigger «конфликт правил»).
