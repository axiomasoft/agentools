### P7.9 — Ошибки и расширяемость: строковые коды, открытые перечисления, must-ignore (§E1–§E3, §E7)

**Intent:** Реализовать двухуровневую модель ошибок (protocol errors ↔ tool execution errors) со строковыми кодами в форме, близкой к RFC 7807, и запретом числового диапазона MCP; открытые перечисления как композицию известных значений + fallback-ветка; правило must-ignore с сохранением сырого события ЦЕЛИКОМ; жизненный цикл значений Active → Deprecated → Removed.
**Why:** Это место, где «работает» и «правильно» расходятся дальше всего. Числовые коды в диапазоне `-32000..-32099` запрещены не стилистически: `-32020..-32099` зарезервирован спекой MCP, и их использование уже вызывало перенумерацию в чужих SDK. Открытые перечисления существуют, чтобы добавление значения не было breaking-изменением автоматически, — голый `enum` делает его таковым молча. Must-ignore MCP НЕ обязывает: ни JSON-RPC, ни ядро MCP не содержат явного MUST об игнорировании неизвестного, поэтому правило пишем мы — и код must-ignore протухает незамеченным именно потому, что в экосистеме из двух потребителей органических случаев расширения почти не бывает (урок IAB, отсюда GREASE-векторы §E4). `RAG:— (repo-grounded: DR-01 §E1 — два уровня ошибок, строковые коды, запрет диапазона MCP, форма RFC 7807; §E2 — oneOf из const + fallback-ветка с шаблоном; §E3 — сырое событие сохраняется целиком, пересборка поле-за-полем запрещена; §E4 — GREASE с первого релиза; §E7 — Active→Deprecated→Removed; research/06-… §8)`.
**Scope Included:** (а) двухуровневая модель: protocol errors (транспортные) и tool execution errors (бизнес/валидационные, возвращаются как результат с признаком ошибки и доступны модели для самокоррекции) — разведение по типам, а не по соглашению; (б) собственные коды — СТРОКОВЫЕ, в структурированном поле, форма объекта ошибки сближена с RFC 7807; числовые коды в `-32768..-32000` не используются вовсе; (в) открытые перечисления: разбор значения по известным `const`-веткам плюс fallback по шаблону `^<product>\.[a-z0-9_]+$`, неизвестное значение НЕ отклоняется; (г) must-ignore (§E3) как правило поведения: неизвестный вид события, неизвестная категория ошибки, неизвестный ключ под нашим префиксом, неизвестное значение открытого перечисления — сообщение принимается И сырое событие сохраняется ЦЕЛИКОМ (носитель — raw-preserving слой P7.3); (д) жизненный цикл значений Active → Deprecated → Removed (§E7): депрецированное значение продолжает валидироваться, удалённое отвергается после окна; (е) прогон GREASE-векторов корпуса (§E4) как обязательное доказательство, с перечнем прогнанных `id`; (ж) тесты, чьи ожидания взяты из векторов `IDE-*`/`OVR-*`, покрывающих §E1–§E3, §E7.
**Scope Excluded:** конкретные коды других подсистем (`descriptor_drift` — P7.4, коды дедупликации — P7.8; здесь заводится ФОРМА, в которой они выражены); raw-preserving носитель как структура (P7.3 — здесь правило его применения); аудит (P7.11); продуктовые расширения `crm.*`/`erp.*` (§E2 — вне обязательного покрытия conformance); ЛЮБЫЕ правки ревизии, схем и корпуса.

**Implementation Rules:** сохранение сырого события делается ЦЕЛИКОМ через носитель P7.3 — пересборка поле-за-полем запрещена (§E3: модель unknown fields протобуфа); открытое перечисление реализуется НЕ голым PHP-enum: известные значения + fallback-ветка, потому что голый enum делает добавление значения breaking-изменением автоматически; числовые коды в диапазоне `-32768..-32000` не появляются в коде ни в каком виде — проверяется грепом; каждая tool execution error возвращается КАК РЕЗУЛЬТАТ с признаком ошибки, а не выбрасывается как протокольная — иначе модель лишается самокоррекции; GREASE-векторы прогоняются раннером фазы P6 против ВРЕМЕННОГО тестового адаптера либо юнит-тестом на тех же данных — способ называется в Completion Notes явно; расхождение с вектором разбирается прогоном против эталонного адаптера, оба вывода — в отчёте; плановый линтер — командой из Phase Context.
**Code Guidance:** Стиль — как в `bakeoff/php/manual/P01OpenEnum.php` (известные константы + fallback-паттерн — это и есть §E2 в коде). Анти-самообман: «must-ignore реализован» ≠ «неизвестное сохраняется» — доказательством считается ПОБАЙТНЫЙ round-trip документа с неизвестным ключом, а не «не упало»; «модель ошибок есть» ≠ «уровни разведены» — нужен тест, показывающий, что бизнес-ошибка возвращается результатом, а не исключением транспорта. Анти-подгонка: если GREASE-вектор красный, чинится must-ignore, а не «уточняется» вектор. ЗАПРЕЩЕНО: голый `enum` для открытых перечислений; числовые коды в зарезервированном диапазоне; пересборка документа поле-за-полем; отклонение сообщения из-за неизвестного значения; удаление значения из перечисления без окна депрекации. If-then: правило ревизии требует отклонить неизвестное значение там, где §E3 требует его игнорировать → это конфликт нормативного текста с решением: `🔴 Blocked` + эскалация (trigger «конфликт правил») с адресатом «владелец», реализация не выбирает сторону молча.
