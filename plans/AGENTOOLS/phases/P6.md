# P6 — Conformance: harness-протокол, раннер, baseline, четырёхслойный CI

## Phase Context

Первая фаза волны реализации (метка `DR-01` §K — «P1 conformance»; прежний номер фазы — P1, см.
карту переименования `plan.md` §4). Делает договор ревизии `2026-08` **исполняемым**: раннер
общается с адаптером каждого SDK построчным JSON по stdin/stdout (`start → config → run × N →
stop`), фикстуры и ожидания принадлежат **раннеру**, реализации не встраиваются друг в друга
(`DR-01` §J1). Severity вердикта выводится из нормативного слова правила, тихого SKIP не
существует — только статус «Not testable» с причиной (§J3). Baseline известных отказов защищён от
протухания: запись, которая начала проходить, — тоже ошибка (§J4). CI — четыре слоя в строгом
порядке, merge блокируется на любом слое и на любом языке (§J5). Golden-файлы имеют канонический
вид и сравниваются двухступенчато (§J7); ревизии и SDK версионируются lockstep (§J8).

**Несущая граница фазы: P6 ничего не нормирует, она нормы ИСПОЛНЯЕТ.** К её старту ревизия
заморожена (P5.2), поэтому расхождение «написано ↔ реализуемо» — дефект ревизии либо корпуса с
ценой «новая датированная ревизия» (D19/D62), а не повод поправить по месту: `🔴 Blocked` +
эскалация с названной ценой. Корпус `fixtures/2026-08/**` фазой P6 не правится **ни на байт** —
включая заведомо красный прогон: вектор-мутант живёт в `conformance/tests/fixtures/mutants/`
(D72). Эталонный адаптер — не источник семантики, а её исполняемое прочтение: при расхождении
адаптера с вектором виновата ОДНА из трёх сторон (адаптер / вектор / текст правила), и это
разбирается, а не подгоняется.

**Что фаза решает сама** — только НАШИ артефакты, ревизией не нормируемые: раскладка
`conformance/**`, драйвер слоёв CI, реестр SDK, форма отчётов (D67). Полный разбор — синтез
`research/05-p6-conformance-harness-2026-08.md`.

**Гейт входа фазы.** Фаза стартует только при терминальной P5 с вердиктом `**Вердикт: GREEN**`
(`artifacts/P5-gate-b.md`), ревизией в статусе `frozen` и существующим аннотированным тегом
`spec-2026-08`: без замороженной ревизии раннер писался бы против движущегося текста, а lockstep
сверял бы манифесты с несуществующим якорем. Между items P6.6 и P6.7 стоит **гейт владельца** —
исход `DR-02` §6 по слою 2 CI (три ветки — Scope P6.7, разбор — D68).

### P6.1 — Раннер: harness-протокол, конфигурация, матчер, отчёт, коды возврата

**Status:** ⬜ Not started
**Intent:** Реализовать `conformance/bin/run` — раннер по НОРМИРОВАННОМУ harness-протоколу ревизии `2026-08`: запуск адаптера отдельным процессом, построчный JSON-диалог `start → config → run × N → stop` с объявлением версии протокола в `start`, загрузка векторов класса `behavior` из корпуса, матчер ожиданий по алгоритму частичного матча корпуса, детерминированный машинный отчёт + человекочитаемая сводка, закрытое перечисление кодов возврата; плюс гигиена дома раннера (переписанный `conformance/README.md`, `composer.json`, коммитимый `composer.lock`).
**Why:** Раннер — механический судья договора: от его корректности зависит смысл слов «SDK зелёный». Дом раннера сейчас пуст и его README указывает на legacy-контракт закрытой ревизии (`init/run/shutdown`, документ `07_conformance-adapter.md`) — исполнитель фазы P7, прочитав его, реализовал бы адаптер против несуществующего протокола. Отдельная цена — различение «отказ SUT» и «отказ раннера»: без разных кодов возврата краш адаптера и дефект самого раннера читаются одинаково, и вина списывается на SDK. `RAG:— (repo-grounded: DR-01 §J1 — последовательность start→config→run×N→stop, фикстуры принадлежат раннеру; findings/P6-conformance-recon-2026-07-27.md §1 — conformance/ содержит ровно один файл README со ссылкой на документ 07 закрытой ревизии, и §4 — что из прежнего ТЗ переносится, а что устарело; plan.md §5 D6 — раннер PHP ≥8.3 CLI без фреймворка)`.
**Scope Included:** (а) CLI `conformance/bin/run --adapter "<команда>" --vectors <корень корпуса> --spec-rev <имя ревизии> [--level L1|L2|L3] [--filter <префикс id>] [--baseline <путь>] [--report <путь>] [--timeout <сек>]`, разбор аргументов без внешних зависимостей; (б) транспорт адаптера: запуск отдельным процессом массив-формой аргументов, неблокирующее чтение stdout/stderr, одна строка = одно сообщение, UTF-8, stdout несёт ТОЛЬКО протокол (логи адаптера — stderr, включаются в диагностику отказа и не глотаются), тайм-аут вектора;
