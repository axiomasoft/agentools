## 3. Дизайн проб bakeoff (вход фазы P2 / A1)

**Вопрос фазы — терпимость, а не разрешение** (`DR-01` §J9): опубликованные схемы содержат
конструкции открытых перечислений (E2), которые генератор обязан пережить, не падая и не теряя
поля. Проверяем это; попутно фиксируем, какие ключевые слова 2020-12 генераторы понимают.

**Корпус проб** (по одной пробе на конструкцию; каждая — минимальная схема + минимальный
валидный документ + документ с неизвестным ключом):

| Проба | Конструкция | Зачем |
|:--|:--|:--|
| `p01-open-enum` | `oneOf` из `const`-ветвей + fallback `string` + `pattern` | E2 — основной приём открытых перечислений |
| `p02-unknown-keyword` | схема с вендорным ключом (`x-agentools-note`) на уровне свойства | терпимость: ключ обязан игнорироваться, поле не теряться |
| `p03-unevaluated` | `unevaluatedProperties: false` на внешнем уровне композиции | J9 — вариант авторинга (закрытая схема); терпимость генератора к незнакомому ключевому слову |
| `p04-dynamic-ref` | `$dynamicRef`/`$dynamicAnchor` | J6 — экзотика 2020-12; ожидаем провал, нужен факт |
| `p05-defs-allof` | `$defs` + `allOf`-композиция базового типа | переиспользуемые подсхемы (E5) |
| `p06-if-then-else` | `if`/`then`/`else` + `dependentSchemas` | условные поля профиля инструмента |
| `p07-prefix-items` | `prefixItems` + `items: false` | кортежи (например, пары хешей) |
| `p08-nested-depth` | вложенность ≥6 уровней + `patternProperties` | лимиты SEP-2106 (DoS-пробы) |
| `p09-ref-local` | относительные `$ref` между файлами ревизии | ловушка `2026-07-draft` (offline-резолв) |
| `p10-numbers` | `integer` minor units, большие числа, `1e21` | сериализация чисел ES6 (JCS-смежное) |

**Кандидаты (эмпирически проверить, а не поверить документации):**

| Сторона | Кандидат | Известное на 2026-07-26 | Локальное окружение |
|:--|:--|:--|:--|
| PHP | `wol-soft/php-json-schema-model-generator` | требует PHP ≥8.4, полное покрытие 2020-12 не подтверждено (`RAG:✅ 2026-07-26 R-11 §10`) | php 8.4.1 — требование выполнимо |
| PHP/Dart | `quicktype` (npm) | кандидат на bakeoff (`RAG:✅ 2026-07-26 R-11 §10`) | node 24.12.0 + npx |
| Dart | `json_schema_builder` | только валидация, не генерация (`RAG:✅ 2026-07-26 R-11 §10`) | dart 3.12.2 |
| Dart | `json_schema` 5.2.2 (BSL-1.0) | валидатор, пин D15/R-09 | — |

Окружение исполнителя проверено 2026-07-27:
`RAG:— (окружение: php 8.4.1 · composer 2.8.3 · node 24.12.0 · npx · dart 3.12.2 · python 3.12.3)`.

**Ожидаемая форма вердикта:** таблица `проба × кандидат` со значениями
`ok` / `ignored-gracefully` / `field-lost` / `crash` / `not-supported`, плюс вывод:
(а) список ключевых слов, разрешённых в **опубликованных** схемах; (б) список, разрешённых в
схемах **авторинга**; (в) роль кодогенерации (J6: каркас типов или отказ от неё в конкретном
языке); (г) вердикт по транспорту Dart.

## 4. Транспорт Dart — критерии решения (item P2.4, закрывает §L-5)

| Критерий | `mcp_dart` 2.3.0-dev.x | Тонкий клиент против `schema.json` |
|:--|:--|:--|
| Эра | dual-era заявлена в prerelease (`RAG:✅ 2026-07-26 R-10 §4`) — нам нужна только modern | ровно modern, лишнего нет |
| Лицензия | MIT (stable 2.2.2) — совместимо с приватным пакетом | своя |
| Стабильность | prerelease; stable отстаёт | наша |
| Что обязано быть доступно | инъекция per-request `_meta` (`protocolVersion`/`clientCapabilities`), `resultType`/`input_required`, `server/discover`, отсутствие принудительного `initialize` | реализуем сами |
| Цена | зависимость на 0.x-prerelease чужого пакета | ~сотни строк + поддержка |
| Риск | dual-era-код тянет legacy-ветки, которых у нас нет как понятия (директива 2026-07-26) | самим держать соответствие пину |

Решение принимается **эмпирически**: smoke-прототип против мок-сервера, а не по README.
Ре-проверка после пина финала MCP (P1) — названный триггер, не «само собой».

## 5. Оркестрация: волны A/B её НЕ объявляют

Критерий (`plan-protocol` §7): N≥3 items с независимым scope **и** детерминированной Validation,
либо длинная автономная цепочка с внешним состоянием.

- P1 (A0): 3 items, но scope последовательно связан (`P1.2` читает пин `P1.1`, `P1.3` — дельты
  `P1.2`) → **manual/item-by-item**.
- P2 (A1): 5 items; P2.1 производит корпус проб, который читают P2.2/P2.3; P2.5 агрегирует →
  сцепка по данным → **manual/item-by-item**.
- P3 (A2): нормативный авторинг с гейтами владельца по тексту → **manual**.
- P4 (A3): кандидат на оркестрацию (векторы по правилам независимы) — решается при детализации
  фазы (проход 2), тогда же пишется скрипт, если критерий сработает.
- P5 (B): один аудит — команда `plan-audit`, не оркестрация.

Прежний скрипт `workflows/wf-agentools-drive.js` написан под структуру фаз до пересборки и
помечен устаревшим (запуск запрещён — D23).
