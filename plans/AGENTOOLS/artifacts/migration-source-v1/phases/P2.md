# P2 — A1: bakeoff генераторов (терпимость к незнакомым ключевым словам) + транспорт Dart

## Phase Context

Волна **A1** по `10_decisions/DR-01_architecture-2026-08.md` §K. Фаза отвечает на два
эмпирических вопроса, от которых зависит форма схем ревизии `2026-08` и раскладка Dart SDK:

1. **Терпимость генераторов кода к незнакомым ключевым словам JSON Schema 2020-12** — не
   «разрешить или запретить `unevaluatedProperties`» (это противоречие снято `DR-01` §J9: схема
   провода открытая, схема авторинга закрытая), а «переживает ли генератор конструкции, которые
   он не понимает, не падая и не теряя поля». Проверять обязательно в любом случае:
   опубликованные схемы содержат открытые перечисления (`DR-01` §E2), которые генератор обязан
   пережить.
2. **Транспортный слой Dart** — брать `mcp_dart` (community, dual-era в prerelease) или писать
   тонкий клиент против `schema.json` (`DR-01` §L-5).

Фаза **эмпирическая**: вердикты выводятся из прогонов с наблюдаемым выводом, а не из чтения
README и не из документации. Каждый прогон воспроизводим командой из артефакта.

> **Контракт фазы (contract-first).** Потребляет: `DR-01` §E2/§E5/§J6/§J9 (что проверяем и
> зачем), §L-5 (открытый вопрос транспорта), `R-11` §10 (кандидаты-генераторы), `R-10` §4
> (состояние Dart-пакетов), `research/01-target-structure-2026-08.md` §3–§4 (корпус проб и
> критерии решения), `findings/P2-bakeoff-recon-2026-07-27.md` (проверенное окружение, внешние
> факты по кандидатам, механика `.gitignore`). **От фазы P1 не потребляет ничего** — стартует
> немедленно (D21). Производит: корпус проб `bakeoff/probes/**` + `bakeoff/.gitignore`, матрицы
> результатов PHP и Dart, выжимку по транспорту, решение `10_decisions/DR-02_…` со списком
> ключевых слов, разрешённых в опубликованных схемах и в схемах авторинга, роль кодогенерации
> (§J6) и вердикт по транспорту Dart, D-записи, Q-9 закрыт. Границы: не пишет ни строки ревизии
> `2026-08` (фаза P3) и не пиннит финал MCP (фаза P1); не реализует SDK (фазы P7/P8).

**Раскладка по репозиториям (D30).** Артефакты фазы (`bakeoff/**`) живут в репозитории
`~/projects/packages/agentools` — все репо-относительные пути в items считаются от его корня, и
команды `Validation` запускаются оттуда, если не сказано иное. Файлы плана (`10_decisions/`,
`findings/`, `open-questions.md`, `plan.md`, `handoff.md`) живут в vault-репозитории `Brain`,
пути к ним даны от корня vault. Закрытие item'а — два коммита в двух репозиториях (`plan.md` §2);
хеш item-коммита для handoff берётся командой
`git -C ~/projects/packages/agentools rev-parse --short HEAD`.

**Гигиена артефактов (D34).** Корневой `.gitignore` репозитория содержит `*.log`: без
переисключения `git add` логов прогонов — молчаливый no-op, и Deliverables не попадают в
item-коммит при зелёной локальной проверке `ls`. Правила игнорирования фазы живут во вложенном

**Гейт выхода (DR-01 §K):** «список разрешённых ключевых слов 2020-12 зафиксирован» —
проверяемо: `10_decisions/DR-02_…` содержит (а) матрицу `проба × кандидат` со значениями из
закрытого перечисления, (б) два явных списка ключевых слов (опубликованные схемы / схемы
авторинга) с обоснованием каждого исключения, (в) вердикт роли кодогенерации по языкам,
