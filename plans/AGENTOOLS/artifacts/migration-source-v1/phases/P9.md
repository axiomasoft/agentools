# P9 — Вертикальный срез в CRM: сквозной сценарий с записью в БД

## Phase Context

Первая продуктовая интеграция (метка `DR-01` §K — «P4 срез CRM»; прежний номер фазы — P4, см. карту
переименования `plan.md` §4). Сотрудник пишет или наговаривает итог дня → агент формирует деловой
черновик → задаёт уточнения → показывает превью → после подтверждения пишет в БД. Работа идёт в
ДВУХ репозиториях кода: пакет `agentools` (продуктовые векторы, донастройки) и контур Flex — по
`architect:package-contribution-protocol` (направление зависимости: потребитель → `agentools/sdk`,
никогда наоборот).

**Несущая граница фазы: P9 ИНТЕГРИРУЕТ, но не нормирует — ни у нас, ни у них.** Вверх: к старту
заморожены ревизия и схемы (P3 + P5.2), корпус `fixtures/2026-08/**` (P4), раннер и
harness-протокол (P6), публичная поверхность PHP SDK (P7) и Dart SDK (P8) — расхождение

(D19/D62/D72) либо эскалация с адресатом-item'ом фазы P7, а НЕ повод поправить по месту. Вбок:
канон CoreX (`ADR-020 AiGateway`, `ADR-022 Agentic Surface Norm`) и блюпринт `B-32` — чужой SSOT
с собственным планом-владельцем (`FLEX-2`, другой корень `plans/`); фаза их НЕ правит — расхождение
оформляется ПРЕДЛОЖЕНИЕМ внутри интеграционного контракта по двухступенчатому гейту вклада.
Полный разбор — синтез `research/08-p9-crm-slice-2026-08.md` §2.
