# P7 — PHP SDK `agentools/sdk` — зелёный на векторах уровня ядра

## Phase Context

Вторая фаза волны реализации и **первая нативная реализация** ревизии `2026-08` (метка `DR-01` §K —
«P2 PHP SDK»; прежний номер фазы — P2, см. карту переименования `plan.md` §4). PHP-first по решению
D14 мастер-плана. Пакет `agentools/sdk` (namespace `AgenTools\`) — ТОНКАЯ библиотека: контракты и
value objects, журнал действия, подтверждение, идемпотентность, ошибки, сценарии, длинные операции,
аудит — без привязки к Laravel/CoreX (интеграция в `corex/ai` — фаза P9 по
package-contribution-протоколу). LLM и доменные инструменты подключаются через порты.
Персистентность — контракты + in-memory реализации (D13).

Реализуются решения `DR-01`, которых в ревизии `2026-07-draft` не было: подписанный self-contained
токен (§B2), пиннинг дескриптора (§B7), журнал как источник истины с
`expected_prev_seq`/`event_version`/снапшотом/хеш-цепочкой (§C1–§C7), реестр эффектов и
fencing-эпоха (§C4), ключ + `args_fingerprint` и три состояния дедупликации (§D1–§D3), строковые
коды ошибок, открытые перечисления и must-ignore (§E1–§E3, §E7), лимиты вычислителя выражений и
`COMPENSATION_FAILED` (§F3–§F4), MRTR как единственный биндинг уточнений (§B1), dual control и
повторная авторизация (§B5, §B8), запрет проброса токенов и тройка принципалов в аудите
(§I1, §I3, §I4).

**Несущая граница фазы: P7 РЕАЛИЗУЕТ, но не нормирует и не переиспользует эталон.** К её старту
заморожены текст ревизии и схемы (P3 + freeze P5.2), корпус `fixtures/2026-08/**` (P4), раннер и
harness-протокол (P6). Расхождение «написано ↔ реализуемо» — дефект ревизии либо корпуса с ценой
«новая датированная ревизия» (D19/D62/D72), а не повод поправить по месту: `🔴 Blocked` + эскалация
с названной ценой. Эталонный адаптер `conformance/adapters/reference/` **не является библиотекой**
(его собственный Scope Excluded говорит это прямым текстом) — копировать его код в `php/src/**`
запрещено: два носителя одной семантики дрейфуют молча. Эталон даёт другое — **диагностику**: перед
объявлением расхождения дефектом ревизии тот же вектор гоняется против эталона, и оба вывода
приводятся (вектор красный на SDK и зелёный на эталоне ⇒ виноват SDK; красный на обоих ⇒ подозрение
на вектор либо текст правила; зелёный на SDK и красный на эталоне ⇒ адресат — фаза P6). Полный
разбор — синтез `research/06-p7-php-sdk-2026-08.md` §2.

**Что фаза решает сама** — только форму НАШЕГО пакета, ревизией не нормируемую: раскладка

**Intent:** Инициализировать `php/` как composer-пакет `agentools/sdk` (namespace `AgenTools\`, PSR-4, PHP ≥8.3): манифест с ре-верифицированными на дату исполнения констрейнтами пинов D15/D77, dev-тулинг (тест-фреймворк + статический анализ), коммитимый `composer.lock` через вложенный `php/.gitignore`, объявление реализуемой ревизии в форме, которую читает `conformance/bin/lockstep`, и переписанный `php/README.md`.

### P7.7 — Подтверждение: Policy/Protocol Layer, подписанный токен, TTL, dual control, событие решения

**Status:** 🟡 In progress
**Intent:** Реализовать документ `04` (правила `CNF-*`) двумя раздельными слоями: Policy Layer (нужен ли гейт, precedence решений) и Protocol Layer (prepare/preview/commit одним инструментом, подписанный одноразовый self-contained токен с покрытием полей §B2, обязательный TTL §B4, `edit` порождает НОВЫЙ prepare §B3, dual control для необратимых §B5, повторная авторизация на commit §B8, обязательное событие решения по схеме §I4).
**Why:** Здесь сходятся деньги и доказуемость. Анти-tampering между preview и commit не даёт нативно ни один из шести разобранных agent-фреймворков — слой целиком наш, и его дефект не ловится ничем снаружи. Четыре отказа токена (подмена аргумента, повтор, просрочка, чужой субъект) обязаны быть РАЗНЫМИ: слитые в один, они не дают вызывающему понять, повторять ли prepare, — а просрочка нормирована как **tool execution error**, а не протокольная ошибка, именно чтобы модель могла повторить сама. Повторная авторизация на commit — защита от классического TOCTOU: между preview и commit проходит произвольное время. ### P7.9 — Ошибки и расширяемость: строковые коды, открытые перечисления, must-ignore (§E1–§E3, §E7)

**Status:** 🟡 In progress
**Intent:** Реализовать двухуровневую модель ошибок (protocol errors ↔ tool execution errors) со строковыми кодами в форме, близкой к RFC 7807, и запретом числового диапазона MCP; открытые перечисления как композицию известных значений + fallback-ветка; правило must-ignore с сохранением сырого события ЦЕЛИКОМ; жизненный цикл значений Active → Deprecated → Removed.
**Why:** Это место, где «работает» и «правильно» расходятся дальше всего.
