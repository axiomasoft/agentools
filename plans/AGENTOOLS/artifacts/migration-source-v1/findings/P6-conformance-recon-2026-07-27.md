## 2. Правила игнорирования — три факта, меняющие раскладку артефактов

```
$ cat .gitignore
/php/vendor/
/php/composer.lock
/dart/.dart_tool/
/dart/.packages
/dart/pubspec.lock
/conformance/vendor/
/conformance/composer.lock
/out/
*.log
.DS_Store

$ git check-ignore -v conformance/composer.lock out/report.json conformance/reports/x.md
.gitignore:7:/conformance/composer.lock	conformance/composer.lock
.gitignore:8:/out/	out/report.json
(третий путь не выведен — не игнорируется)
```

| Факт | Следствие |
|:--|:--|
| `/conformance/composer.lock` игнорируется | версии зависимостей раннера не фиксируются в репозитории → слой CI невоспроизводим между машинами. Лечится **вложенным** `conformance/.gitignore` с `!composer.lock` (механика проверена в этом же репозитории item'ом P2.1 — `bakeoff/.gitignore` переисключает `!results/*.log` из-под корневого `*.log`, D34). Корневой `.gitignore` не правится |
| `/out/` игнорируется | транзитные отчёты прогона (`out/report.json`) в репозиторий не попадут — это нормально; **коммитимый** артефакт гейта (отчёт покрытия по уровням) обязан лежать вне `out/` |
| `conformance/reports/**` НЕ игнорируется | пригодный дом для коммитимых отчётов гейта |

## 4. Прежнее ТЗ раннера — где лежит и что из него берётся

Прежняя фаза «P1 — Conformance: adapter-протокол, runner, CI» (4 items, ревизия `2026-07-draft`)
была переписана пересборкой; её текст жив в git-истории vault-репозитория:

```
git show 7411115:05-Projects/03-Packages/AgenTools/plans/AGENTOOLS/phases/P1.md
```

(файл `phases/P1.md` стал фазой A0 коммитом `93c17ce`; `7411115` — версия до пересборки.)

**Что оттуда переносится по существу** (реанкор на ревизию `2026-08` — механика D28):

- раннер — PHP ≥8.3 CLI без фреймворка, адаптер запускается отдельным процессом, обмен построчным
  JSON (D6, подтверждено `DR-01` §J1);
- матчер — чистые функции над массивами, единственное место `proc_open`, массив-форма аргументов
  (без интерполяции в shell-строку);
- эталонный («null») адаптер как микро-референс семантики: отличает дефект раннера от дефекта SDK;
- самотест: зелёный прогон корпуса + заведомо красный прогон вектора-мутанта;
- шаги CI = ровно локальные команды (никакой «CI-магии»), чтобы гейт воспроизводился локально 1:1;
- честная пометка «remote отсутствует, CI не запускался».

**Что оттуда НЕ переносится** (устарело пересборкой):

- последовательность `init/run/shutdown` и документ `07_conformance-adapter.md` — заменены
  `start → config → run × N → stop` и документом `11_conformance-harness.md` (§J1);
- уровни только L1/L2 у самотеста — корпус `2026-08` несёт три класса векторов и три уровня;
- «дописать отложенные L3-векторы» — векторы пишет фаза P4 и они замораживаются гейтом P5; фаза P6
  корпус не правит;
- разрешение «добавить в документ 02 явное разрешение мини-правкой» — после freeze правка ревизии
  невозможна в принципе (правка = новая датированная ревизия, D19/D62).
