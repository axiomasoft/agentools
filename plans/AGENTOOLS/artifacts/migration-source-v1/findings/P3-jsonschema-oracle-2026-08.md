# P3 — официальный Draft 2020-12 oracle для schema-values gate

**Дата проверки:** 2026-08-04  
**Источник:** https://python-jsonschema.readthedocs.io/en/stable/validate/  
**Локальный факт:** `python3 -m pip show jsonschema` → версия `4.10.3`; импорт
`jsonschema.Draft202012Validator` доступен в текущем окружении.

## Выжимка

Официальная документация `python-jsonschema` называет `Draft202012Validator` версионным
валидатором JSON Schema Draft 2020-12. Его `check_schema(schema)` проверяет схему против
метасхемы, а `validate(instance)`/`iter_errors(instance)` исполняют семантику схемы над
значением. Если `$schema` присутствует, `validators.validator_for(schema)` выбирает класс
валидатора по URI диалекта; для наших адресных подсхем безопаснее задавать
`Draft202012Validator` явно, потому что вынутый `$defs`-узел собственного `$schema` не несёт.

## Вердикт для P3

`tools/spec_lint.py` не должен расширять собственный частичный интерпретатор ещё двумя
keyword-ветками: такой путь снова оставит неизвестную часть Draft семантики без сигнала.
Основной lint остаётся stdlib-only, но адресный `--schema-values-selftest` получает ленивый
oracle `Draft202012Validator` и обязан завершаться ненулевым кодом, если библиотека недоступна.
Инструмент не устанавливает зависимость и не обращается к сети сам. `RAG:✅ 2026-08-04:
официальная документация python-jsonschema, Schema Validation / Validator protocol`.

Две обязательные мутации второго аудита различаются реальной семантикой:

1. `maxLength: 1` на fallback делает строку `vendor.extension` невалидной;
2. дополнительная ветвь `{ "type": "integer" }` делает число `7` валидным для всего
   `oneOf`, то есть контракт перестаёт быть строковым перечислением.

Обе мутации должны одновременно: (а) получить ожидаемый семантический приговор oracle и
(б) быть отвергнуты структурным fail-closed gate с точным JSON pointer. Несовпадение этих
двух слоёв — красный selftest, а не повод добавить очередной молчаливый shortcut.
