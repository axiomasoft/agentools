## 2. Правила игнорирования на PHP-стороне

```
$ git check-ignore -v php/composer.lock php/composer.json php/src/X.php php/conformance/adapter.php
.gitignore:2:/php/composer.lock	php/composer.lock
(остальные три пути не выведены — не игнорируются)
```

| Факт | Следствие |
|:--|:--|
| `/php/composer.lock` игнорируется корневым `.gitignore` | версии зависимостей SDK не фиксируются → **слой 3 четырёхслойного гейта CI** (тесты каждого SDK, `DR-01` §J5 + D75) невоспроизводим между машинами. Тот же класс, что `conformance/composer.lock` в фазе P6 (D67); лечится тем же механизмом — **вложенным** `php/.gitignore` с `!composer.lock` (переисключение проверено в этом репозитории item'ом P2.1, D34). Корневой `.gitignore` не правится. Развилка «библиотеки lock не коммитят» разобрана в синтезе §6 и решена D80 |
| `php/src/**`, `php/conformance/**`, `php/composer.json` НЕ игнорируются | пригодные дома для кода SDK и его conformance-адаптера; отдельного правила не требуется |

**Ловушка, названная явно.** Локальный интерпретатор — 8.4.1, а объявленный порог пакета — **PHP

непроверяемым. Это прямо влияет на выбор пинов (§4).

## 4. Свежесть пинов `D15` на PHP-стороне — RAG 2026-07-27

`D15` (принят 2026-07-10 по `20_research/R-08_library-pins.md`) назвал для PHP **имена** пакетов, но
не констрейнты версий. Ниже — ре-верификация на дату исполнения и вычисленные констрейнты.
Метод: `packagist.org` через WebFetch (первоисточник метаданных пакета) + Perplexity Web для
вопросов, на которые страница пакета не отвечает.

| Пин `D15` | Наблюдаемый факт (источник, дата) | Вердикт |
|:--|:--|:--|
| JSON Schema 2020-12 → `opis/json-schema` | v**2.6.0** (2025-10-17), PHP `^7.4 \|\| ^8.0`, Apache-2.0, «supports all keywords from all drafts (draft-2020-12 down to draft-06)», ~45 млн установок, 240 dependents, 0 security advisories `RAG:✅ 2026-07-27 https://packagist.org/packages/opis/json-schema` | **ПОДТВЕРЖДЁН.** Констрейнт `^2.6`. Порог PHP ≥8.3 не задевается |
| ULID → `symfony/uid` | текущая стабильная — v**8.1.0** (2026-05-29), требует **PHP >= 8.4.1**; линия **7.4** требует PHP ≥8.2, последний патч v**7.4.9**; MIT; ULID + UUID v1/v3–v8 `RAG:✅ 2026-07-27 https://packagist.org/packages/symfony/uid` + `RAG:✅ 2026-07-27 Perplexity Web (symfony.com/releases, endoflife.date/symfony)` | **УТОЧНЁН: `^7.4`, не `^8.0`.** Взять текущую мажорную линию значило бы поднять порог пакета до PHP ≥8.4.1 и молча отменить объявленный ≥8.3. `R-08` §ULID писал «активная линия 8.x» — на 2026-07-10 это было верно как факт о пакете, но не как констрейнт для нашего порога |
| JCS (RFC 8785) → `mmccook/php-json-canonicalization-scheme` | v**1.0.0** (2023-08-07) — единственный релиз, PHP `^8.1`, MIT, **11 833 установки, 0 dependents, 3 звезды**, автообновление Packagist активно (последнее 2026-07-09) `RAG:✅ 2026-07-27 https://packagist.org/packages/mmccook/php-json-canonicalization-scheme`. Утверждение «проходит официальные JCS-тесты» принадлежит **автору пакета**; независимого подтверждения на дату проверки не найдено, рекомендация источника — «confirm against the upstream JCS test vectors in your own CI before shipping» `RAG:✅ 2026-07-27 Perplexity Web (сравнение PHP-реализаций RFC 8785; упомянута историческая альтернатива `aywan/php-json-canonicalization` без подтверждения поддержки)` | **СОХРАНЁН С НАЗВАННЫМ РИСКОМ.** Один релиз трёхлетней давности, ноль зависимых пакетов, один мейнтейнер — на этом стоит `descriptor_digest`, `args_fingerprint` и хеш-цепочка журнала, то есть межъязыковой байтовый инвариант. Митигация — не «доверять README», а прогнать официальные векторы RFC 8785 своим тестом (item P7.3); альтернатива на случай провала (писать JCS самим) уже принята для Dart тем же `D15` |
| QA-тулинг (`D15` не пинил — назначается этой фазой) | PHPUnit: последняя **13.2.5** (2026-07-25) требует **PHP >= 8.4.1**; линия **12** документирована как минимум PHP **8.3**, последняя 12.5, bugfix-поддержка до 2027-02-05 `RAG:✅ 2026-07-27 https://packagist.org/packages/phpunit/phpunit` + `RAG:✅ 2026-07-27 Perplexity Web (phpunit.de supported-versions)`. PHPStan: **2.2.6** (2026-07-26), PHP `^7.4\|^8.0`, MIT `RAG:✅ 2026-07-27 https://packagist.org/packages/phpstan/phpstan` | **ПИНЫ: PHPUnit `^12`, PHPStan `^2.2`.** PHPUnit `^13` отклонён по той же причине, что `symfony/uid` `^8`: он требует PHP ≥8.4.1 и сделал бы объявленный порог ≥8.3 непроверяемым (§3) |

**Сводка одной строкой.** Из четырёх пинов `D15` на PHP-стороне один подтверждён без изменений
(`opis/json-schema`), один уточнён констрейнтом (`symfony/uid` `^7.4`), один сохранён с названным
риском и обязательным собственным доказательством (`mmccook/…`), плюс здесь же назначены два
QA-пина, которых `D15` не касался. Единый мотив трёх из пяти строк — **объявленный порог PHP ≥8.3**:
свежайшая мажорная версия трёх из пяти пакетов требует 8.4.1 и порог бы отменила.

## 6. Границы этой разведки

- Состояние ревизии `2026-08`, корпуса `fixtures/2026-08/**` и раннера `conformance/**` **не
  снималось**: на дату разведки их не существует (фазы P3/P4/P6). Все ссылки items фазы P7 на эти
  артефакты — на их будущее содержимое, гарантированное контрактами фаз-производителей.
- Лицензии Dart-пакетов (`R-08` открытый вопрос) здесь не проверялись — предмет фазы P8.
- Версии в §4 верны **на 2026-07-27**. Фаза P7 стартует после P6, то есть заведомо позже; item P7.1
  обязан ре-верифицировать три констрейнта на СВОЮ дату (правило — в его `Implementation Rules`),
  а не принять эту таблицу на веру: расхождение датированной выжимки с фактом на дату исполнения —
  ровно тот дефект, ради которого `D15` вообще перепроверялся.
