# Synthetic knowledge golden journey

This runnable host composes the existing single `AdvanceRun` loop, trusted intake,
claims, immutable responses, usage and destination delivery with optional knowledge
ingest/retrieval/invalidation. Support and education-like documents are fictional,
nonpersonal UTF-8 fixtures. The teacher-shaped task role lives in a snapshot block;
both scenarios retain the existing read-only host shell and its pinned bundle.
No school models or pedagogical truth are added to core.

`HostValidator` is the existing Pipeline `Validator` hook adapted to an external
`DomainGold`. Missing/unavailable gold returns unknown and cannot publish a
host-domain-gated release. Generic integrity checks run first and cannot be
approved away by domain gold. The conformance `ScriptedGold` uses independent
formula/unit anchors. It proves those fixture rules only. There is no expert
baseline or live deployment qualification; educational qualification remains
`insufficient_evidence`, including when technical fixture checks pass.

`ScriptedExtractor` maps pages, fragments, navigation and cards to deterministic
UTF-8 byte ranges and normalized boxes. It is not an OCR/PDF adapter. `PgIndex`
is an example host adapter using real PostgreSQL tsvector/GIN with pre-authorized
exact tenant/release constraints. Cached candidates still go through fresh
source/disclosure checks. The context compiler prunes optional evidence within
the token budget and retains mandatory policy/current input. The scripted model
can echo only selected immutable evidence and returns no citation when none fits.

The composition registers release -> bundle/snapshot/cache use, keeps historical
response facts unchanged, and refuses stale source disclosure at invocation and
buffered destination boundaries. `GuardedTransport` preserves the known pre-send
refusal versus uncertain post-IO distinction. SIGKILL recovery verifies the saved
same-request provider outcome without another generation or usage fold.
Provider, admission, owner and destination ports are explicitly scripted.

The example requires the proven isolated test database environment accepted by
`IsolatedDatabase`, never a development or production DSN:

```sh
php examples/platform/knowledge/run.php support
php examples/platform/knowledge/run.php education
```

It creates and removes its own schema in that isolated database. The owning
acceptance command is `python3 tools/platform_gate.py e2e --scenario knowledge-journey`.
It provisions isolated PostgreSQL when no explicit isolated test DSN is supplied.
No live calls, pricing claims, production rollout, external erasure claim or
classical mutation testing are included.
