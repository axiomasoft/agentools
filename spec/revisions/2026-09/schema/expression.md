# Грамматика языка выражений ревизии `2026-09`

> Файл — **единственный носитель** грамматики языка выражений и семантики его вычисления.
> Он нормативен целиком в силу правила `SCN-13` документа `06_scenarios.md`: продукции,
> таблица приоритетов, семантика типов, закрытый перечень ошибок вычисления и таблица
> контрольных точек ниже имеют ту же нормативную силу, что строка правила. Дублирование
> грамматики прозой в любом документе ревизии запрещено тем же правилом.
> Ревизия спеки: `2026-09` (состав и статус — `README.md`). Нормативные ключевые слова — по
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

Язык намеренно минимален: он читает значения и сравнивает их, и ничего больше. Минимальность
здесь не эстетика, а условие паритета двух реализаций — чем меньше язык, тем меньше площадь,
на которой PHP и Dart могут разойтись. Импорт готового языка отклонён фактами разведки, а не
вкусом: у единственного кандидата с полноценным набором соответствия обе реализации на Dart
частичны, что внесло бы дрейф на уровне спецификации самого языка.

Места употребления выражения — два, и оба заданы документом `06`: условие исполнения шага
(`when`) и значения отображения аргументов (`input_map`, включая `compensate.input_map`).

---

## 1. Продукции

Нотация — ISO/IEC 14977 EBNF; `(* … *)` — комментарий. Пробелы между токенами незначимы и
отбрасываются разбором.

```ebnf
Expression   = OrExpr ;
OrExpr       = AndExpr , { "||" , AndExpr } ;
AndExpr      = NotExpr , { "&&" , NotExpr } ;
NotExpr      = { "!" } , Comparison ;
Comparison   = Primary , [ ( "==" | "!=" ) , Primary ] ;
Primary      = "(" , Expression , ")"
             | Missing
             | Reference
             | Literal ;

Missing      = "missing" , "(" , Reference , ")" ;   (* единственная функция языка *)

Reference    = ContextRef | StepsRef ;
ContextRef   = "$ctx" , "." , Path ;
StepsRef     = "$steps" , "." , Identifier , "." , Path ;
Path         = Identifier , { "." , Identifier } ;
Identifier   = ( Letter | "_" ) , { Letter | Digit | "_" } ;

Literal      = String | Number | Boolean | Null ;
String       = '"' , { StringChar | Escape } , '"' ;
Escape       = "\" , ( '"' | "\" | "/" | "n" | "t" | "r" ) ;
Number       = [ "-" ] , Digit , { Digit } , [ "." , Digit , { Digit } ] ;
Boolean      = "true" | "false" ;
Null         = "null" ;

Letter       = "A" | … | "Z" | "a" | … | "z" ;
Digit        = "0" | … | "9" ;
```

Приоритет операторов от низкого к высокому: `||` ниже `&&`, `&&` ниже `!`, `!` ниже `==` и
`!=`. Скобки меняют группировку явно.

Конструкции, которых в языке **нет** и появление которых есть синтаксическая ошибка: любые
функции, кроме `missing`; арифметика; операторы порядка; присваивание; индексация; вызов
метода; конкатенация; обращение к переменной вне двух корней раздела 2. Расширение языка
выходит новой датированной ревизией, а не правкой этого файла.

## 2. Ссылки на данные

Корней ровно два:

- `$ctx.<path>` — контекст прогона сценария (например `$ctx.today`, `$ctx.tenant`);
- `$steps.<id>.<path>` — результат ранее исполненного шага с идентификатором `<id>`
  (например `$steps.extract.text`).

`<path>` — точечная навигация по полям объекта. Разыменование отсутствующего пути **вне**
`missing(…)` есть ошибка вычисления, а не «пустое значение»: молчаливый `null` на месте
опечатки — самая дорогая форма расхождения двух реализаций, потому что она не наблюдается.
Для безопасной проверки наличия существует ровно одна конструкция — `missing(…)`, аргументом
которой всегда является укоренённая ссылка, а не голый путь.

Шаг, отказавший и продолженный маршрутом `continue` (`06_scenarios.md` `SCN-11`), результата
не имеет: ссылка на него ведёт себя как ссылка на неисполненный шаг.

## 3. Семантика типов и операторов

Равенство **строгое, без приведения типов**:

- `==` истинно тогда и только тогда, когда операнды одного типа и равны по значению;
- разнотиповое сравнение даёт `false` и ошибкой **не** является;
- `!=` есть отрицание `==`;
- сравнимые типы: строка, число, логическое значение, `null`; числа сравниваются по значению,
  и `0.9 == 0.90` истинно.

Логические операторы применимы **только** к логическим операндам: не-логический операнд у
`&&`, `||` или `!` есть ошибка типов. Вычисление `&&` и `||` идёт слева направо с сокращением:
правый операнд не вычисляется, если результат определён левым. Порядок вычисления
детерминирован — от него зависит, сработает ли лимит обхода, и потому он часть контракта, а не
свойство реализации.

## 4. Ошибки вычисления

Перечень закрыт:

1. разыменование отсутствующего пути вне `missing(…)`;
2. ошибка типов — не-логический операнд у `&&`, `||`, `!`, либо результат `when`, не
   являющийся логическим значением;
3. синтаксическая ошибка разбора;
4. превышение любого из лимитов вычислителя (`06_scenarios.md` `SCN-16`…`SCN-19`).

Любая из них есть **технический** отказ шага и маршрутизируется `on_technical_fail`
(`06_scenarios.md` `SCN-6`, `SCN-21`). Семантическим отказом ошибка вычисления не бывает
никогда: домен здесь ни при чём, не состоялось само вычисление.

Вычисление выполняется **обходом дерева разбора** (`06_scenarios.md` `SCN-14`). Ни одна из
ошибок этого перечня не является поводом обратиться к средствам динамического исполнения
host-языка — их в контракте нет вовсе.

## 5. Контрольные точки

Строки таблицы — нормативные контрольные точки: реализация, расходящаяся с любой из них,
проваливает соответствующий вектор корпуса. Контекст вычисления для всех строк:

```
$ctx = {
  "today":  "2026-09-03",
  "tenant": "acme",
  "flag":   true,
  "draft":  { "status": "ready", "items": 3, "parent": null }
}
$steps = {
  "extract": { "text": "…", "confidence": 0.9, "ok": true },
  "clarify": { "answered": false }
}
(поля $ctx.optional и $steps.review НЕ заданы)
```

| # | Выражение | Результат | Что фиксирует |
|:--|:--|:--|:--|
| E1 | `$ctx.today == "2026-09-03"` | `true` | корень `$ctx`, строковый литерал, `==` |
| E2 | `$ctx.draft.status == "ready"` | `true` | вложенный путь |
| E3 | `$steps.extract.confidence == 0.9` | `true` | корень `$steps`, числовой литерал |
| E4 | `$ctx.draft.status != "sent"` | `true` | `!=` |
| E5 | `$ctx.flag && $steps.extract.ok` | `true` | `&&` над логическими значениями данных |
| E6 | `!$steps.clarify.answered` | `true` | `!` от `false` |
| E7 | `$ctx.draft.items == 3 \|\| $ctx.flag` | `true` | `\|\|` с сокращением |
| E8 | `missing($ctx.optional)` | `true` | `missing`, отсутствующий путь |
| E9 | `missing($ctx.today)` | `false` | `missing`, существующий путь |
| E10 | `$ctx.draft.parent == null` | `true` | литерал `null` |
| E11 | `(missing($steps.review.done) \|\| $ctx.flag) && !$steps.clarify.answered` | `true` | скобки и комбинация |
| E12 | `$ctx.today == 2026` | `false` | строгое сравнение разных типов |
| E13 | `$ctx.optional == "x"` | ошибка вычисления (технический отказ) | разыменование отсутствующего пути вне `missing` |
| E14 | `$ctx.draft.items && true` | ошибка типов (технический отказ) | `&&` над числом |
| E15 | `$ctx.today == exec("id")` | синтаксическая ошибка (технический отказ) | вызов, которого в языке нет: попытка инъекции host-кода отвергается разбором |

E1–E11 покрывают все конструкции грамматики. E12 фиксирует отсутствие приведения типов,
E13–E14 — обе категории ошибок данных, E15 — наблюдаемое следствие запрета режима компиляции
(`06_scenarios.md` `SCN-15`): попытка инъекции не доходит до вычисления, потому что языка для
неё не существует.
