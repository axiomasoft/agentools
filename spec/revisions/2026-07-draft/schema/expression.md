# Грамматика выражений AgenTools (`expression.md`)

> Ревизия спеки: `2026-07-draft`. Нормативные ключевые слова — по
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) (MUST / SHOULD / MAY).
> Нормативный документ, использующий грамматику, — `../04_scenario-schema.md`
> (правила `SC-*`). Решение D10 плана `AGENTOOLS`: язык выражений намеренно
> минимален (только чтение переменных, никакого `eval`/`compile`), чтобы его
> реализация на PHP и Dart была тривиальной и байт-в-байт совпадающей.

Выражения используются в двух местах шага сценария:

- `when` — условие исполнения; MUST вычисляться в **boolean** (`SC-9`);
- значения `input_map` / `compensate.input_map` — вычисляемый аргумент; результат
  любого типа (ссылка или литерал), передаётся инструменту/модели (`SC-5`).

Ошибка вычисления выражения (см. §4) = **technical_fail** шага (`SC-30`), маршрутизируется
`on_technical_fail`.

---

## 1. EBNF

Грамматика (нотация ISO/IEC 14977 EBNF; `(* … *)` — комментарии). Пробелы между
токенами незначимы и отбрасываются.

```ebnf
Expression   = OrExpr ;
OrExpr       = AndExpr , { "||" , AndExpr } ;
AndExpr      = NotExpr , { "&&" , NotExpr } ;
NotExpr      = { "!" } , Comparison ;
Comparison   = Unary , [ ( "==" | "!=" ) , Unary ] ;
Unary        = Primary ;
Primary      = "(" , Expression , ")"
             | Missing
             | Reference
             | Literal ;

Missing      = "missing" , "(" , Reference , ")" ;   (* единственная функция языка *)

Reference    = ContextRef | StepsRef ;
ContextRef   = "$ctx" , "." , Path ;
StepsRef     = "$steps" , "." , Identifier , "." , Path ;
Path         = Identifier , { "." , Identifier } ;
Identifier   = ( Letter | "_" ) , { Letter | Digit | "_" } ;

Literal      = String | Number | Boolean | Null ;
String       = '"' , { StringChar | Escape } , '"' ;
Escape       = "\" , ( '"' | "\" | "/" | "n" | "t" | "r" ) ;
Number       = [ "-" ] , Digit , { Digit } , [ "." , Digit , { Digit } ] ;
Boolean      = "true" | "false" ;
Null         = "null" ;

Letter       = "A" | … | "Z" | "a" | … | "z" ;
Digit        = "0" | … | "9" ;
```

Приоритет операторов (от низкого к высокому): `||` < `&&` < `!` < `==`/`!=`.
Скобки `(` … `)` меняют группировку явно.

**Что запрещено (v1, D10/D11):** любые функции, кроме `missing`; арифметика; операторы
порядка (`<`, `>`, `<=`, `>=`); присваивание; индексация `[…]`; вызовы методов;
конкатенация. Расширение грамматики — только новой ревизией спеки.

## 2. Ссылки на данные

**Корни ровно два** (`SC-26`):

- `$ctx.<path>` — контекст сессии (напр. `$ctx.today`, `$ctx.tenant`);
- `$steps.<id>.<path>` — результат ранее исполненного шага с идентификатором `<id>`
  (по умолчанию = `id` шага, либо его `output_bind`), напр. `$steps.extract.text`.

`<path>` — dot-нотация из идентификаторов (буквы/цифры/`_`), навигация по вложенным
полям объекта результата. Ссылка на несуществующий путь **вне** `missing(...)` —
ошибка вычисления (§4), а не «пустое значение» (`SC-27`). Именно для безопасной
проверки наличия существует `missing`.

`missing(Reference)` → `true`, если путь ссылки отсутствует (шаг не исполнялся, поле не
задано); иначе `false` (`SC-28`). Аргумент `missing` — всегда укоренённая ссылка
(`$ctx.…`/`$steps.…`), не голый путь.

## 3. Семантика типов и операторов

**Строгое равенство, без коэрсии** (`SC-29`):

- `==` истинно ⟺ операнды **одного типа** И равны по значению; иначе `false`.
  Разнотиповое сравнение (напр. строка vs число) — **не ошибка**, а `false`.
- `!=` — отрицание `==`.
- Сравнимые типы: string, number, boolean, null. Числа сравниваются по значению
  (`0.9 == 0.90` → `true`).

**Логические операторы требуют boolean-операндов** (`SC-29`):

- `&&`, `||`, `!` применимы только к boolean. Не-boolean операнд у логического оператора —
  **ошибка типов** (§4).
- `&&` и `||` вычисляются с short-circuit слева направо (правый операнд не вычисляется,
  если результат уже определён левым); порядок детерминирован.

## 4. Ошибки вычисления

Ошибка вычисления возникает при (перечень закрытый):

1. **дереференс отсутствующего пути** вне `missing(...)` (`SC-27`);
2. **ошибка типов** — не-boolean операнд у `&&`/`||`/`!`, либо результат `when` не boolean
   (`SC-9`, `SC-29`);
3. **синтаксическая ошибка** разбора выражения.

Любая из них = **technical_fail шага** (`SC-30`). Рантайм MUST реализовать вычисление
**AST-интерпретатором** (разбор → дерево → обход), без обращения к `eval`/`compile`
host-языка (`SC-31`, D10 плана) — это гарантия одинакового поведения PHP и Dart и
защита от инъекций.

## 5. Таблица примеров (нормативные контрольные точки)

Контекст вычисления для всех строк ниже:

```
$ctx = {
  "today":  "2026-07-10",
  "tenant": "acme",
  "flag":   true,
  "draft":  { "status": "ready", "items": 3, "parent": null }
}
$steps = {
  "extract": { "text": "…", "confidence": 0.9, "ok": true },
  "clarify": { "answered": false }
}
(поля $ctx.optional и $steps.review НЕ заданы)
```

| # | Выражение | Результат | Конструкция |
|:--|:--|:--|:--|
| E1 | `$ctx.today == "2026-07-10"` | `true` | `$ctx`, строковый литерал, `==` |
| E2 | `$ctx.draft.status == "ready"` | `true` | вложенный path |
| E3 | `$steps.extract.confidence == 0.9` | `true` | `$steps`, числовой литерал |
| E4 | `$ctx.draft.status != "sent"` | `true` | `!=` |
| E5 | `$ctx.flag && $steps.extract.ok` | `true` | `&&`, boolean-литералы данных |
| E6 | `!$steps.clarify.answered` | `true` | `!` от `false` |
| E7 | `$ctx.draft.items == 3 \|\| $ctx.flag` | `true` | `\|\|`, short-circuit |
| E8 | `missing($ctx.optional)` | `true` | `missing()`, отсутствующий путь |
| E9 | `missing($ctx.today)` | `false` | `missing()`, существующий путь |
| E10 | `$ctx.draft.parent == null` | `true` | литерал `null` |
| E11 | `(missing($steps.review.done) \|\| $ctx.flag) && !$steps.clarify.answered` | `true` | скобки, комбинация |
| E12 | `$ctx.today == 2026` | `false` | строгое сравнение разных типов (без коэрсии) |
| E13 | `$ctx.optional == "x"` | **ошибка вычисления** (technical_fail) | дереференс отсутствующего пути вне `missing()` |
| E14 | `$ctx.draft.items && true` | **ошибка типов** (technical_fail) | `&&` над числом слева |

Строки E1–E11 покрывают все конструкции грамматики (`$ctx`, `$steps`, вложенный path,
`==`, `!=`, `&&`, `||`, `!`, скобки, `missing()`, литералы string/number/boolean/null).
E12–E14 фиксируют семантику строгого равенства и обе категории ошибок вычисления. Эти
строки — контрольные точки для тест-векторов P0.9.
