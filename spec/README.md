# spec/

Нормативная спецификация AgenTools. Ревизии — датированные и immutable после
заморозки (паттерн Model Context Protocol): следующие изменения идут в новую
ревизию, а не в опубликованную.

**Имя каталога ревизии — финальное сразу** (D19). Прежняя конвенция
«разрабатываем под временным именем, после стабилизации переименовываем» отменена:
переименование ломает внешние ссылки и `$id` схем ровно в тот момент, когда на
ревизию уже начали ссылаться. Статус ревизии живёт в её собственном `README.md`
и снимается гейтом фазы плюс git-тегом, а не переименованием каталога.

| Ревизия | Против MCP | Статус |
|:--|:--|:--|
| `revisions/2026-07-*` | 2025-11-25 | историческая, не патчится (D18) |
| `revisions/2026-08` | 2026-07-28 | frozen |
| `revisions/2026-09` | 2026-07-28 | candidate (PLAN1 hardening successor) |

Каждая ревизия содержит нормативные документы (`NN_<slug>.md` с пронумерованными
правилами вида `EXT-1`, `ALC-T3`, …) и соответствующие JSON Schema
(`schema/*.json`, диалект 2020-12). Документ описывает СЛОВАМИ то, что схема
описывает СТРУКТУРОЙ — оба обязаны быть согласованы; расхождение — дефект ревизии.

Проверка целостности: `python3 tools/spec_lint.py spec/revisions/<имя ревизии>`.
Конвенции у ревизий разные, поэтому линтер выбирает профиль по имени каталога;
имя без профиля — ошибка, а не молчаливая проверка чужими правилами.
